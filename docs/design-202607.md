# gnss-scope 実装設計（202607）

**実装の設計書**（構成・データモデル・実装上の注意）。役割分担は次のとおり。

| 文書 | 内容 |
|---|---|
| `funcspec-202607.md` | 機能仕様（何をするか・仕様値） |
| `usersGuide-202607.md` | 利用者の手引（操作手順・画面の読み方） |
| **`design-202607.md`（本書）** | 実装設計（画面実装・データモデル・モジュール構成・リファクタ記録） |
| `algospec-202607.md` | 算出式・自動判定ロジックの詳細 |
| `hardware-202607.md` | 機器・ファーム（Pico W / MAX-M10S / BLE）の仕様 |

本書は、前身 `gnss-tracker`（地理院地図の全画面表示がメイン）を **`gnss-scope`** として
再構築した際の設計を出発点としている。受信パイプライン（BLE → 行復元 → NMEA パース →
エポック確定 → 受信品質統計）の考え方は前身から引き継いでおり、
**変更点は UI 構成・記録モデル・解析の対象**である。

## 1. 方針

- **地図をメインにしない。** 地図は5タブのうちの1つ。役割も「ライブ地図」から
  「**load した記録の GNSS 値をマーカー表示する**」へ移す（ライブ現在地表示は副機能として残す）。
- **記録は静止点のばらつき評価に一本化。** 1回の記録 = 1地点。
  旧「スナップショット記録（1点だけ即保存）」は廃止し、`record → stop → save` に統一。
  旧「静的測位記録」の収集・集計・収束自動停止ロジックはそのまま流用する。
- **解析は SkyPlot / SNR / DOP / DRMS の4本立て**とし、ライブと読込データの双方を同じ画面で見る。

```

│ ステータスバー（常設）        │  接続状態ドット / 状態 / REC / fix / 最終受信
├──────────────────────────────┤
│ ページ（タブで排他・全画面）  │  接続 / 記録 / 解析 / 地図 / 設定
```

旧構成（地図全画面 ＋ 下部ボタンで開くボトムシート）を廃止し、`.page` の排他表示に変更した（`js/tab-ui.js`）。
非表示中の `<canvas>` と Leaflet はサイズが 0 になるため、**タブ表示時に描き直す**：

| タブ | 表示時の処理 |
|---|---|
| 記録 | `recScatter.redraw()` |
| 解析 | `analysisUI.refresh()`（現在のソースで全再描画） |
| 地図 | `mapView.invalidateSize()` ＋ 読込データへフィット |
| 設定 | `infoUI.refresh()`（アプリ更新の確認） |

`CanvasView.redraw()` を追加し、「サイズ 0 のまま描いた分の描き直し」を共通化した。

## 3. 記録モデル（record → stop → save → load）

```
record ──連続エポック収集──> stop ──集計──> [未保存の記録 pending] ──save──> IndexedDB
                                                                              │
                                                            load ◀────────────┘
                                                              ▲
                                            JSON ファイル ──importer.js──┘
```

- `stop` は **DB に書かない**。集計結果を pending として返し、記録タブに散布図＋凡例＋
  測位結果（折りたたみ）を表示する。
  停止理由（`converged` / `timeout` / `maxEpochs` / `manual` / `interrupted`）と、
  収束判定を働かせていたか（`autoStop`）も pending に持つ。後者は停止サマリで
  「未収束」と「収束判定なし」を書き分けるために要る（`algospec-202607.md` 3-5）。
- `save` で地点名（既定 `yyyy-mm-dd-xx` の同日連番）とメモを付けて保存し、保存した記録を
  そのまま「読込データ」に設定する（解析タブ・地図タブへ即反映）。
  このとき調査日（`surveyId`）と地点番号（`pointNo`）を採番し、ツリーの根 `surveys` も用意する（4. 参照）。
- 収束自動停止（`algospec-202607.md` 3.）は維持。自動停止も `stop` と同じ経路で pending になる。
- 記録中は Wake Lock を取得する。

### 画面 OFF は一時停止ではなく中断停止

`visibilitychange` で `document.hidden` になってから **5 秒**（`app.js` の `HIDDEN_GRACE_MS`）
戻らなければ `recorder.stop('interrupted')` で打ち切る。復帰しても続きは再開せず、
次の記録は別の地点になる。

- 画面が消えると BLE が切れてデータが届かない。一時停止で粘ると、**穴の空いた区間が
  1 地点として残る**。地点単位で 2 系統を比べる用途では、これが後から効いてくる。
- 猶予を置くのは、`document.hidden` が画面 OFF 以外（他アプリへの切替・着信・
  通知シェード・カメラ起動）でも立つため。地図を一瞬見る／現場写真を撮るといった
  短い離脱で毎回やり直しになるのを避ける。
- この方針により `Recorder` / `DeviceGnss` から `paused` 状態を撤去した。
  収集中かどうかは `current` の有無だけで決まる（状態が 1 つ減る）。
- 秒数と点数を併記する停止サマリ（`180秒/50点` など）が、中断で欠けたぶんの手掛かりになる。

### サンプルに衛星リストを含める

保存サンプル（`toSample`）に `satellites: [{sys, prn, elev, azim, snr, used}]` を追加した。
これにより **保存後・取込後でも任意エポックの SkyPlot / SNR を再現**できる（解析タブのスライダ）。
容量は 1 エポックあたり衛星30個程度 = 数KB、180 エポックで数百KB程度に収まる。

## 4. データモデル（IndexedDB: `gnssScopeDB` v2）

DB 名は旧 `gnssDB` から変更した（旧アプリのデータと混ざらないようにするため）。

1日に何十地点もまわって 2系統（GNSS受信機の NMEA と Android内蔵の測位）を比べる使い方に合わせ、
**調査日 → 地点 → 実データ**のツリーにしている。

```
surveys   '2026-07-31'                     ← 根：1日の調査
 └ sessions  rec_<開始ms> ＋ surveyId / pointNo   ← 枝：1地点（20地点なら20件）
    └ points   sessionId ＋ surveyId / pointNo    ← 葉：その地点の実データ
                 samples[]       GNSS受信機のパース済みエポック（30〜180秒ぶん）
                 rawNmea[]       GNSS受信機の生NMEA行
                 deviceSamples[] Android内蔵GNSS の測位
```

| ストア | キー | 内容 |
|---|---|---|
| `surveys` | `id`（`yyyy-mm-dd`） | `{ id, label, memo, createdAt, updatedAt }` |
| `sessions` | `id`（`bySurvey` index） | `{ id, type:'record', surveyId, pointNo, label, memo, createdAt, endedAt, window, summary, (importedAt, sourceId, sourcePointNo) }` |
| `points` | `id`（`bySession` index） | `{ id, sessionId, surveyId, pointNo, kind:'record', stats, samples[], (rawNmea[], deviceSamples[], deviceStats) }` |
| `settings` | `key` | `tileCacheMeta` のみ（事前DLしたタイルの版・種別・日時）|

- `summary`: `{ lat, lon, altMSL, count, drms, cep50, cep95, stopReason, autoStop, rxStats, rawLines, rawTruncated, (deviceDrms, deviceCount) }`
  - `autoStop` は収束判定を働かせていたか。停止サマリの但し書きの出し分けに使う。
    この項目を持たない旧データは「未収束」に寄せて表示する。
- `stats`: `computeStaticStats()` の戻り値（中心・中央値・東西/南北標準偏差・DRMS/2DRMS・CEP50/CEP95・
  標高平均/標準偏差・fix内訳・平均DOP・平均衛星数・**平均C/N0**・散布図オフセット）
- 設定キーは旧 `staticMinSec` などから `minSec` 等へ改名（記録が静的測位専用ではなくなったため）。
- **設定タブの値は `settings` ストアへ保存しない**（既定値は `js/constants.js`）。端末に残った
  古い値が新しい既定値を覆い隠すのを避けるため。`settings` ストアに残るのは、Cache Storage の
  実体と対応する端末側の状態（`tileCacheMeta`）だけ。旧版が書き込んだ設定キーは読まれず放置される。

### 地点の対応をどう保証するか

**2系統を同じ `point` レコードに入れる**のが第一の担保で、これで「どちらの系統のどのデータが
対か」は構造上ずれない。その上で、後から見て「本当に同じ時間に測ったか」を確認できるよう
`session.window`（`js/survey.js` の `buildWindow`）を残す。

| フィールド | 内容 |
|---|---|
| `startedAt` / `endedAt` / `durationSec` | record → stop の記録区間（端末時計） |
| `gnss` | 受信機のエポックが実際に取れていた範囲 `{startedAt, endedAt, durationSec, count}` |
| `gnssUtc` | 同じ範囲を GPS時刻(UTC)で見たもの |
| `device` | Android内蔵の測位が取れていた範囲 |
| `overlap` | `{ overlapSec, coverGnss, coverDevice, deviceInRecording, deviceTotal }` |
| `clockOffsetMs` | 端末時計 − GPS時刻。2系統を同じ時間軸へ並べ直すときの補正量 |
| `deviceLagMs` | Android内蔵の 受信時刻 − 測位確定時刻。古い fix を返していないかの目安 |

時刻軸の扱いに注意が要る。受信機のサンプルは `t`＝GPS時刻 / `recvAt`＝端末時計、
Android内蔵は `t`＝OS が測位を確定した時刻 / `recvAt`＝アプリが受け取った時刻で、
**`t` どうしは別の時計**（内蔵は `maximumAge:0` でも数秒前の fix を返すことがある）。
区間の突き合わせは両者が共通に持つ `recvAt` で行い、`t` とのズレは
`clockOffsetMs` / `deviceLagMs` として別に残す。

`overlap.deviceInRecording` は**記録区間**を基準に数える。受信機の最初のエポックは
複数センテンスが揃うまで確定せず1秒強かかるため、`gnss` の範囲で数えると
記録開始直後に届いた内蔵のサンプルを取りこぼす。また、静止中は OS が更新を間引いて
内蔵が1〜数点しか来ないことがあり、割合（`coverDevice`）だけでは対応を判断できない。

地点番号 `pointNo` は同じ `surveyId` の中の連番で、**欠番は再利用しない**（最大値＋1）。
一度出した対応表と番号がずれないようにするため。

### 生NMEA行の保存

設定 `saveRawNmea`（既定 ON）のとき、受信した行を `point.rawNmea = [{ t, line }]` に
そのまま残す。パースを通す前に分岐させるので、チェックサムNG行や `$PPICO` も含まれる
（「受信したそのまま」を残す意味）。後から RTKLIB などの別ツールで再解析できる。

容量は 1Hz・10〜20行/秒で 1地点（30〜180秒）あたり 40〜250KB、20地点/日で 3〜5MB 程度。
上限 20000 行（`MAX_RAW_LINES`）を超えたぶんは捨て、本数を `summary.rawTruncated` に残して
記録が途中までであることを隠さない。

### v1 → v2 の移行

`onupgradeneeded` の versionchange トランザクション内で完結させる（`migrateToV2`）。
`surveys` ストアと `sessions.bySurvey` を作り、既存の記録には `createdAt` のローカル日付から
`surveyId` を、同じ日の中では `createdAt` 昇順で `pointNo` を採番して `points` にも複写する。
これで過去データもそのまま調査日ツリー・対応表に載る。

### Android内蔵GNSS の並行取得（比較データ）

`deviceSamples` / `deviceStats` / `summary.deviceDrms` は **並行取得した記録にだけ足す**
（取得していない記録の形は従来のまま＝後方互換。取込側も任意扱いで読む）。

- `deviceStats` は `computeDeviceStats()` の戻り値 ＝ `computeStaticStats()` の全項目 ＋
  `avgAccuracy` / `dupCount` / `offsetFromRef {e, n, distM, bearingDeg}`。
  ばらつきの定義を受信機側と共有するため、集計本体は `computeStaticStats` をそのまま使う。
- `offsetFromRef` の基準は **GNSS受信機の中心**。散布図で共通原点に重ねる際の平行移動量
  そのものなので、描画側は差分を再計算せず `offsetFromRef.e / .n` を足すだけでよい。
- `dupCount`（直前と完全同一座標の点数）は保存後・取込後も再計算できるよう
  サンプル列から算出する（フラグとしてサンプルに持たせない）。

### エクスポート / インポート

地点ごと（`file-io.js`）:

- CSV: 1行1エポック。列に `snr_avg_used_dbhz`（使用衛星の平均 C/N0）と `recv_at_local` を持つ。
  末尾に地点の識別（`survey_id` / `point_no`）と集計値をコメント行で付ける。
  Android内蔵は行として混ぜず、`# device_*` のコメント行で比較値のみ出す。
- GPX: 記録の中心を `wpt`、生エポック群を `trk` として出力（GNSS受信機のみ）。
- NMEA: `point.rawNmea` の行をそのまま `.nmea` として出力（先頭に地点を示すコメント行）。
- JSON: `{ app:'gnss-scope', format:1, exportedAt, session, point }`。

調査日ごと（1日20地点をまとめて持ち出す）:

- 対応表CSV: **1行1地点**で2系統を横並びにした表（`compareRow` / `COMPARE_HEADER`）。
  列名の接頭辞 `gnss_*` / `dev_*` が系統を表す（機種名は入れない）。
  先頭2列が `survey_id` / `point_no` で、これが地点の対応そのもの。
  ばらつき（DRMS / CEP / 標準偏差）に加え、`center_offset_m`・`drms_ratio_dev_over_gnss`、
  対応の検証列（`overlap_s` / `cover_*_pct` / `dev_in_record_window` / `clock_offset_ms` / `dev_fix_lag_ms`）を持つ。
  2系統比較の入口はこのファイル。
- バンドルJSON: `{ app:'gnss-scope', format:2, exportedAt, survey, points:[{session, point}] }`。
  `point` を丸ごと入れるので生NMEA・生エポック・Android内蔵の測位が地点ごとに揃ったまま出る。

取込（`importSessionFile`）は単体（format 1）・バンドル（format 2）を同じ入口で受け、
常に `{session, point}` の配列を返す。取込時は **必ず新 id を採番**し（同じファイルの二重取込でも
上書きしない）、元 id は `sourceId`、元の地点番号は `sourcePointNo` に残す。
調査日は元データの日付をそのまま使い（同じ日の測定は同じ調査日に集まる方が突き合わせやすい）、
地点番号だけ取込先で採り直す。`stats` が欠けている JSON は `computeStaticStats` で再計算する。

## 5. 解析タブ

| 表示 | ライブ | 読込データ |
|---|---|---|
| SkyPlot / SNR | 最新エポック | スライダで選んだエポック（保存済み衛星リストから再現） |
| DOP（バー＋数値・測位モード・衛星数・精度ソース・GST σ） | 最新エポック | 同上 |
| DRMS（散布図＋集計テキスト） | 記録中／直近の記録の暫定集計 | 読込データの確定集計 |
| DRMS の比較系列（Android内蔵） | 同区間の暫定集計（記録中から見える） | `point.deviceStats` |

- レイアウトは 2 列グリッド（`.an-grid`）。上段 SkyPlot / DRMS、下段 SNR / DOP。
  見出し（`.sub-head`）と本体（`.an-cell`）を別セルにして、見出しの行数が違っても左右の図の上端が揃うようにしている。
  行数の多い DRMS 集計テキストは `.an-wide` で 2 列ぶち抜き。
  列幅に追従させるため `grid-template-columns` は `minmax(0, 1fr)`（canvas の内在サイズに列幅を引っ張られないように）。
- ソースはラジオで切替。読込データが無い間は「読込データ」を `disabled` にする。
- 保存サンプル → 表示用エポックへの変換（`sampleToEpoch`）で `recvAt` を補い、
  `canvas-view.js` のキャリーフォワード判定（`holdDecision`）がライブと同じ経路で働くようにしている。
- 系統別内訳は、ライブでは GSA 由来の `usedBySys` / `inViewBySys` を使い、
  無い場合（読込データ）は衛星リストから数える。
- 比較系列は `ScatterPlotView.update(stats, deviceStats)` の第2引数で渡す。
  基底クラスのリサイズ再描画は `update(this._last)` と1引数で呼ぶため、第2引数の既定値を
  **保持中の系列（`this._lastDevice`）** にしてある（比較を消すときは明示的に `null` を渡す）。
- `update()` は表示範囲の外に出た点数 `{ gnss, device }` を返す。呼び出し側（記録タブ・解析タブ）が
  「表示範囲の外側に N 点」を凡例の下に出す（`algospec-202607.md` 6-4）。
- 表示半径はヒステリシス付きでビューが保持する。**別のデータへ切り替えるときは
  `resetScale()` を呼ぶ**（記録開始時、解析タブのソース切替時・`setLoaded` 時）。
  呼ばないと前の記録のスケールを引きずる。
- 統計円のラベルは**種別のみ**（`CEP50` / `DRMS`）で、系統は色で表す。象限を分けて描くのは、
  比較系列を重ねるとスケールが大きい方に引かれ、受信機側の円が小さくなってラベルが
  中心で潰れるため。中心からの距離にも下限（10 px）を設けている。
- 系統は色だけでなく**形**でも分ける（塗り＝GNSS受信機 / 中抜き＝Android内蔵）。
  屋外の直射日光下と色覚特性の両方で、色だけの区別は落ちるため。凡例の記号も同じ規則。

## 6. モジュール構成

「1機能＝1ファイル」を基準に、**受信 / 解析・記録 / 画面**の3層で分ける
（202607 のリファクタリングで 27 ファイル → 17 ファイルに統合。詳細は 9.）。

| 層 | モジュール | 責務 |
|---|---|---|
| エントリ | `app.js` | 受信パイプラインと各タブの結線のみ ＋ 中断停止の猶予判定 |
| 共通 | `constants.js` | 設定の既定値と 2 系統の表示名・色（`SERIES`） |
| 共通 | `view-utils.js` | `$`（DOM ショートハンド）・タブ切替・表示フォーマッタ・停止サマリ |
| 受信 | `transport.js` | BLE(NUS) 接続・自動再接続 ＋ 開発用モック（同じ `onFrame` I/F） |
| 受信 | `nmea.js` | 行復元（`LineBuffer`）＋ センテンス解析 ＋ チェックサム（`xorChecksum`） |
| 受信 | `epoch.js` | 同一時刻センテンス群 → 1エポック |
| 受信 | `stream-stats.js` | 受信品質統計（$PPICO 突合を含む） |
| 受信 | `device-gnss.js` | Android内蔵GNSS（Geolocation API）の並行取得。記録中のみ `watchPosition` |
| 解析・記録 | `accuracy.js` | 水平精度推定・DRMS/CEP 集計・収束判定 |
| 解析・記録 | `charts.js` | Canvas 描画（共通土台 ＋ スカイプロット / SNR / 散布図） |
| 解析・記録 | `recorder.js` | record / stop / save の制御 |
| 解析・記録 | `beep.js` | 自動停止の通知音（AudioContext。記録ボタンで unlock） |
| 解析・記録 | `survey.js` | 調査日→地点のID体系・測定区間・対応検証（純粋関数のみ） |
| 解析・記録 | `storage.js` | IndexedDB ラッパ（v1→v2 移行を含む） |
| 解析・記録 | `file-io.js` | CSV / GPX / NMEA / JSON 出力・調査日バンドルと対応表・JSON 取込 |
| 画面 | `connect-ui.js` | 接続タブ（受信経路のライフサイクル・受信品質パネル・モック切替） |
| 画面 | `record-ui.js` | 記録タブ（record/stop/save/load・進捗バー・凡例・一覧・Wake Lock） |
| 画面 | `analysis-ui.js` | 解析タブ（SkyPlot / SNR / DOP / DRMS、ライブ↔読込切替） |
| 画面 | `map.js` | 地図タブ（`MapView` ＋ タブ配線） |
| 画面 | `settings-ui.js` | 設定タブ（各種設定 ＋ アプリ更新確認） |
| 画面 | `tile-cache.js` | オフラインタイル事前DL（`TileCache` ＋ 設定タブ内のUI） |

- `app.js` は結線のみ。DOM 操作はタブごとの `*-ui.js` が持つ。
- 読込データ（`loaded`）は `app.js` が保持し、`setLoaded()` で解析タブ・地図タブへ配る。
- `device-gnss.js` は「受信経路」であってライフサイクルを持たないため、開始/停止は
  `Recorder` が握る（記録区間＝取得区間を自明にする）。`app.js` は
  `onSample → recorder.addDeviceSample` / `onStatus → recordUI.onDeviceStatus` を結線するだけ。
- **画面に出る系統名は `constants.js` の `SERIES` だけから引く。**
  受信機の機種を替えたときに追従漏れが起きないようにするため、各モジュールに
  ラベルを直書きしない（テスト側も `SERIES` を参照する）。
- 廃止：旧「ライブ」タブ（記録タブの「現在の測位値」へ統合）／旧「情報」タブ（設定タブへ統合）／
  スナップショット記録／記録の一時停止（画面 OFF は中断停止へ。3. 参照）。

## 7. PWA・オフラインタイル

- 版数は `sw.js` の `APP_VERSION`（`'yyyy-mm-dd.n'` = 更新日 ＋ 同日内の連番。日付が変われば 1 に戻す）。
  シェルキャッシュ名は `gnss-scope-shell-${APP_VERSION}`（接頭辞は `activate` の掃除で
  他キャッシュと区別するためのもの）。`settings-ui.js` は `APP_VERSION` を正規表現で読み取り、
  接頭辞なしの版数で表示・比較する（旧SWがキャッシュ名を返す場合は接頭辞を外す）。
  `APP_SHELL` には全モジュールを列挙する。
- 地理院タイルは cache-first でキャッシュ `gsi-tiles` に格納する。Service Worker（実行時の
  取得）と事前ダウンロード（`tile-cache.js`）が**同じキャッシュ名を共有**する点が要。
- 未キャッシュのタイルをオフラインで要求した場合は 504 を返し、Leaflet 側でグレー表示にする。

### タイルマニフェスト（`data/tile_manifest.json`）

事前ダウンロードの対象を座標リストで持つ（Format A）。マニフェストは `data/` を唯一の置き場とし、
ルート直下に複製を置かない。

```json
{
  "version": "2026-06-01",
  "layers": {
    "<任意のキー>": { "z": 17, "tiles": [[x, y], [x, y], ...] }
  }
}
```

- `z` はズームレベル、`tiles` は当該ズームのタイル座標 `[x, y]` の配列。
- URL は選択中の地図種別のテンプレート（`GSI_LAYERS[mapType].url`）の `{z}/{x}/{y}` を置換して生成する。
  したがって**地図種別を変えると、その種別のタイルは再取得が必要**。
- `version` は取得時に `settings.tileCacheMeta` へ記録し、オフラインでも取得済み内容を表示できるようにする。

## 8. リファクタリング（202607・機能変更なし）

ファイル数が多く（27）、似た処理が分散していたため、**機能を変えずに**統合・整理した。

### 8-1. ファイルの統合（27 → 17）

| 統合後 | 統合したファイル | まとめた理由 |
|---|---|---|

| `file-io.js` | `exporter` + `importer` | 記録のファイル入出力。JSON 形式の定義を1か所に持てる |
| `view-utils.js` | `format` + `tab-ui` + `$` ヘルパ | 画面共通のユーティリティ。`$` を各モジュールへ引数で配る配線が不要になる |

| `record-ui.js` | `record-ui` + `wake-lock` | 「記録中の画面維持」は記録機能の一部 |
| `connect-ui.js` | （`app.js` から分離・新規） | 接続制御と受信品質パネルを app.js から切り出し |

`app.js` は結線のみに絞り 330 行 → 162 行。各 UI モジュールは自分が使う描画ビューを
