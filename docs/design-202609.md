# gnss-scope 実装設計（202609）

**実装の設計書**（構成・データモデル・実装上の注意）。役割分担は次のとおり。

| 文書 | 内容 |
|---|---|
| `funcspec-202609.md` | 機能仕様（何をするか・仕様値） |
| `usersGuide-202609.md` | 利用者の手引（操作手順・画面の読み方） |
| **`design-202609.md`（本書）** | 実装設計（画面実装・データモデル・モジュール構成・リファクタ記録） |
| `algospec-202609.md` | 算出式・自動判定ロジックの詳細 |
| `hardware-202609.md` | 機器・ファーム（Pico W / MAX-M10S / BLE）の仕様 |

本書は、前身 `gnss-tracker`（地理院地図の全画面表示がメイン）を **`gnss-scope`** として
再構築した際の設計を出発点としている。受信パイプライン（BLE → 行復元 → NMEA パース →
エポック確定 → 受信品質統計）の考え方は前身から引き継いでおり、
**変更点は UI 構成・記録モデル・解析の対象**である。

## 1. 方針

- **地図をメインにしない。** 地図はタブのうちの1つ。役割も「ライブ地図」から
  「**load した記録の GNSS 値をマーカー表示する**」へ移す（ライブ現在地表示は副機能として残す）。
- **記録は静止点のばらつき評価に一本化。** 1回の記録 = 1地点。
  旧「スナップショット記録（1点だけ即保存）」は廃止し、`record → stop → save` に統一。
  旧「静的測位記録」の収集・集計・収束自動停止ロジックはそのまま流用する。
- **解析は SkyPlot / SNR / DOP / DRMS の4本立て**とし、ライブと読込データの双方を同じ画面で見る。

## 3. 記録モデル（record → stop → save → load）

```
record ──下書き作成──> 収集中 ──5エポックごとに追記──> IndexedDB（chunks）
                          │                                  ▲
                        stop ──集計──> 下書きへ集計値を書く ──┘
                          │
                        save ──採番して確定──> 地点 ──load──> 解析 / 地図
                                                  ▲
                              JSON ファイル ──file-io.js──┘
```

- `record` は **DB に下書きを作ってから**収集を始める。作れなければ記録しない
  （残せない記録を始めても仕方がない）。先に親を作るので孤児チャンクが発生しない。
- 収集中は **5 エポック（≒5 秒）ごとに `chunks` へ追記**する。**保存を押す前に落ちても
  直近の追記までは残る**のがこの設計の要点。詳細は 4. の「実データを分割して追記する」。
- `stop` は集計して pending を返し、記録タブに散布図＋凡例＋測位結果を表示する。
  DB への書き込み（残りのバッファ＋集計値）は**描画の後**に走らせる（`await` しない）。
  停止理由（`converged` / `timeout` / `maxEpochs` / `manual` / `stalled` / `storageError`）と、
  収束判定を働かせていたか（`autoStop`）を `summary` に持つ。後者は停止サマリで
  「未収束」と「収束判定なし」を書き分けるために要る（`algospec-202609.md` 3-5）。
- `save` は**確定**操作。地点番号（`pointNo`）を採番し、地点名（既定 `yyyy-mm-dd-xx`）と
  メモを付けて `status` を `confirmed` にする。**実データには触らない**（メタの更新だけ）。
  確定した記録をそのまま「読込データ」に設定する（解析タブ・地図タブへ即反映）。
- 収束自動停止（`algospec-202609.md` 3.）は維持。自動停止も `stop` と同じ経路を通る。
- 記録中は Wake Lock を取得する。

### 下書きを挟む理由

停止した時点で「地点」にしてしまうと、測り直した失敗記録が地点番号を消費して番号が飛び、
出力（対応表・パッケージ）や調査日の平均DRMS にも混ざる。かといって停止まで DB に書かないと、
保存を押す前に落ちたときに全損する。**書くのは早く、地点にするのは遅く**が下書きの役割。

- 下書きは `pointNo: null`。`nextPointNo` は `Number.isFinite(s.pointNo)` を見るので、
  下書きは採番から自動的に外れる。
- 集計・エクスポートは `isConfirmed(session)`（`status !== 'draft'`）で絞る。
- 一覧では調査日の先頭に出る（`pointNo ?? 0` の並びで先頭に来る）。**再起動後もそこから確定できる**。
- 中身のある下書きは自動削除しない。ただし起動時に `chunks` を 1 件も持たない下書き
  （最初の追記より前に落ちたもの）だけは片付ける（`cleanupEmptyDrafts`）。失うものが無いため。

### 打ち切りは「画面が隠れたか」ではなく「データが来ているか」

記録中だけ 1 秒間隔のタイマーを回し、最後のエポックから **10 秒**（`recorder.js` の
`STALL_MS`）過ぎたら `stop('stalled')` で打ち切る。

- 停止判定（収束・`maxSec`・`maxEpochs`）は `addEpoch` の中にしか無い。**エポックが届かなく
  なると判定自体が走らず、記録が凍る。** 旧版の `visibilitychange` による中断停止は
  このうち画面 OFF の場合しか塞いでいなかった（BLE 切断・電池切れ・fix 喪失では凍ったまま）。
- 判定の基準は「蓄積対象になったエポックを受けた時刻」。`addEpoch` は fix の無いエポックを
  弾くので、**fix 喪失も途絶として扱う**（測位できていない状態で記録を続ける意味は無い）。
- 記録に使う端末は**記録専用**とする前提。地図・写真は別の端末で見る。これにより
  「短い離脱で毎回やり直しになるのを避ける」ための猶予（旧 5 秒）が不要になった。
- 10 秒にしているのは、BLE の瞬断が自動再接続（`transport.js`）で復帰するまでの猶予。
- `Recorder` / `DeviceGnss` に `paused` 状態は持たない。収集中かどうかは `current` の有無だけ。
- 秒数と点数を併記する停止サマリ（`180秒/50点` など）が、欠けたぶんの手掛かりになる。

### サンプルに衛星リストを含める

保存サンプル（`toSample`）に `satellites: [{sys, prn, elev, azim, snr, used}]` を追加した。
これにより **保存後・取込後でも任意エポックの SkyPlot / SNR を再現**できる（解析タブのスライダ）。
容量は 1 エポックあたり衛星30個程度 = 数KB、180 エポックで数百KB程度に収まる。

## 4. データモデル（IndexedDB: `gnssScopeDB` v3）

DB 名は旧 `gnssDB` から変更した（旧アプリのデータと混ざらないようにするため）。

1日に何十地点もまわって 2系統（GNSS受信機の NMEA と Android内蔵の測位）を比べる使い方に合わせ、
**調査日 → 地点 → 実データ**のツリーにしている。

```
surveys   '2026-07-31'                     ← 根：1日の調査
 └ sessions  rec_<開始ms> ＋ surveyId / pointNo / status   ← 枝：1地点（20地点なら20件）
    ├ points   sessionId ＋ surveyId / pointNo / stats     ← 葉：その地点の集計値
    └ chunks   sessionId ＋ seq                            ← 葉：実データ（5エポックずつ）
                 samples[]       GNSS受信機のパース済みエポック
                 rawNmea[]       GNSS受信機の生NMEA行
                 deviceSamples[] Android内蔵GNSS の測位
```

| ストア | キー | 内容 |
|---|---|---|
| `surveys` | `id`（`yyyy-mm-dd`） | `{ id, createdAt, updatedAt, (exportedAt) }` |
| `sessions` | `id`（`bySurvey` index） | `{ id, type:'record', status:'draft'\|'confirmed', surveyId, pointNo, label, memo, createdAt, endedAt, window, summary, (confirmedAt, importedAt, sourceId, sourcePointNo) }` |
| `points` | `id`（`bySession` index） | `{ id, sessionId, surveyId, pointNo, kind:'record', stats, (deviceStats) }` |
| `chunks` | `id`（`bySession` index） | `{ id:`<sessionId>_<seq>`, sessionId, seq, samples[], (rawNmea[], deviceSamples[]) }` |
| `photos` | `id`（`bySession` index） | `{ id:`<sessionId>_ph<seq>`, sessionId, seq, blob, bytes, w, h, addedAt }` |
| `settings` | `key` | `tileCacheMeta` のみ（事前DLしたタイルの版・種別・日時）|

- `status`: `'draft'` = 停止したがまだ地点になっていない / `'confirmed'` = 保存（確定）済み。
  判定は `isConfirmed(session)`（`storage.js`）に集約する。下書きは `pointNo: null`。
- `summary`: `{ lat, lon, altMSL, count, drms, cep50, cep95, stopReason, autoStop, rxStats, rawLines, rawTruncated, (deviceDrms, deviceCount) }`
  - 記録中は追記のたびに `count` / `rawLines` / `deviceCount` / `bytes` だけを更新する。
    停止せずに落ちた記録でも「どこまで録れているか」が一覧に出るようにするため。
  - `bytes` / `photoBytes` / `photoCount` は端末内サイズの集計用（下記）。
- 調査日は**テキストを持たない**（日付そのものが識別子で、書くことは地点側にある）。
  `exportedAt` は出力ZIP を書き出した日時で、`updatedAt` を下回れば「未書き出し」に戻る。
  - `autoStop` は収束判定を働かせていたか。停止サマリの但し書きの出し分けに使う。
    この項目を持たない旧データは「未収束」に寄せて表示する。
- `stats`: `computeStaticStats()` の戻り値（中心・中央値・東西/南北標準偏差・DRMS/2DRMS・CEP50/CEP95・
  標高平均/標準偏差・fix内訳・平均DOP・平均衛星数・**平均C/N0**・散布図オフセット）
- 設定キーは旧 `staticMinSec` などから `minSec` 等へ改名（記録が静的測位専用ではなくなったため）。
- **設定タブの値は `settings` ストアへ保存しない**（既定値は `js/constants.js`）。端末に残った
  古い値が新しい既定値を覆い隠すのを避けるため。`settings` ストアに残るのは、Cache Storage の
  実体と対応する端末側の状態（`tileCacheMeta`）だけ。旧版が書き込んだ設定キーは読まれず放置される。

### 実データを分割して追記する（chunks）

停止時に `rawNmea` を 1 回で書く設計だと、最大 1.6MB の structured clone がメインスレッドに
乗るうえ、**そこへ至る前に落ちれば全損**する。そこで実データを `points` から外し、
記録しながら `chunks` へ 5 エポックずつ追記する。

- **粒度はエポック境界。** 生行は `addRawLine`、パース結果は `assembler.add` と別経路で流れ
  （`app.js`）、`addEpoch` の時点が「このエポックと、その間に受けた生行」が揃う唯一の
  タイミング。ここで区切れば 2 系統の対応がずれず、1 トランザクションにまとめられる。
- 1 エポックごと（1 tx/秒）でも動くが、トランザクションが 5 倍になる割に、得られるのは
  「失う量が 5 秒 → 1 秒」だけ。60 秒の記録の末尾 5 秒を失っても集計はほとんど動かない。
- **追記のみ。既存チャンクは読まない・書き直さない。** これで総シリアライズ量が
  O(全バイト数) に収まる（成長中の配列を毎回書き直すと O(n²) になる）。
- 1 チャンクは約 20KB。structured clone はサブミリ秒で、毎エポック既に走っている
  `computeStaticStats` と散布図の canvas 再描画のほうがずっと重い。
  受信経路を待たせないよう **`await` しない**で呼ぶ。
- フラッシュ後は生行バッファを捨てられるので、メモリに残るのは現在のバッファだけ。
  `MAX_RAW_LINES` はメモリ圧迫の保険ではなく **DB 容量の保険**という意味に変わった。
- 失敗したぶんはバッファへ戻して次のチャンクで再試行し、連続 3 回で `stop('storageError')`。
- **fix 喪失中はフラッシュが走らない**（`addEpoch` が弾くため）が、途絶停止が 10 秒で
  打ち切るので溜まる量には上限が付く。時間ベースのフラッシュは併用しない。
- 読み出しは `getPointsBySession()` がチャンクを `seq` 順に結合し、**従来と同じ形の
  `point`（`samples` / `rawNmea` / `deviceSamples` 入り）を返す**。解析タブ・地図・
  エクスポートの呼び出し側は分割を意識しない。取込データも 1 チャンクとして入れ、
  読み出し経路を 1 本に保つ。

### 端末内のデータ量を自分で数える

`navigator.storage.estimate()` はオリジン全体を返すため、事前ダウンロードした地図タイル
（Cache Storage に数十MB）が混ざって**記録データの量が分からない**。そこで自前で数える。

- 数えるのは**フラッシュのとき**（`JSON.stringify(data).length` を積む）。停止時に数えると
  書き終えたチャンクを読み戻すことになる。20KB の JSON 化は誤差の範囲で済む。
- 写真は `blob.size` をそのまま足す（こちらは正確）。
- 合計は `sessions` だけで数えられるよう、`summary.bytes` / `photoBytes` に持たせる
  （`storage.getStorageUsage()`）。地点を消せば自動で辻褄が合う。
- **JSON の文字数は IndexedDB の実使用量ではない**（structured clone の形式とインデックスの
  オーバーヘッドが乗る）。同じオーダーには収まるので警告の判断には足りるが、表示は「約」を付ける。
- しきい値は `constants.js` の `STORAGE_LIMITS`（警告 50MB / 想定上限 100MB）。
  超えても**記録は止めない**（現場で測れなくなる方が困る）。警告を出し続けて整理を促す。

### 地点の写真

`photos` ストアへ**縮小済みの JPEG を Blob のまま**入れる（base64 は 33% 増えるうえ、
表示のたびにデコードが要る）。`chunks` と同じ `bySession` の形にしてあるので、
削除・容量集計・読み出しの経路をそのまま流用できる。

- 縮小は**取り込む時点**で行う（`photo-ui.js`）。後から縮められないため。
  長辺を設定値に収めたうえで、200KB に入るまで JPEG 品質を段階的に落とす。
- EXIF の向きは `createImageBitmap` の `imageOrientation:'from-image'` に任せる
  （自前で EXIF を読むと端末ごとの差分を抱え込む）。
- 枚数とバイト数は `session.summary` にも複写する。一覧の各行や容量集計で
  `photos` ストアを引き直さずに済ませるため。
- 表示は `URL.createObjectURL`。**貼り替えのたびに `revokeObjectURL` する**（貯めると端末を圧迫する）。

### 地点の対応をどう保証するか

**2系統を同じチャンクに入れる**のが第一の担保で、これで「どちらの系統のどのデータが
対か」は構造上ずれない。その上で、後から見て「本当に同じ時間に測ったか」を確認できるよう
`session.window`（`js/survey.js` の `buildWindow`）を残す。

| フィールド | 内容 |
|---|---|
| `startedAt` / `endedAt` / `durationSec` | record → stop の記録区間（端末時計） |
| `gnss` | 受信機のエポックが実際に取れていた範囲 `{startedAt, endedAt, durationSec, count}` |
| `gnssUtc` | 同じ範囲を GPS時刻(UTC)で見たもの |
| `device` | Android内蔵の測位が取れていた範囲 |
| `overlap` | `{ overlapSec, coverGnss, coverDevice, deviceInRecording, deviceTotal }` |
| `clockOffsetMs` | 端末時計 − GPS時刻。2系統を同じ時間軸へ並べ直すときの補正量 |
| `deviceLagMs` | Android内蔵の 受信時刻 − 測位確定時刻。古い fix を返していないかの目安 |

時刻軸の扱いに注意が要る。受信機のサンプルは `t`＝GPS時刻 / `recvAt`＝端末時計、
Android内蔵は `t`＝OS が測位を確定した時刻 / `recvAt`＝アプリが受け取った時刻で、
**`t` どうしは別の時計**（内蔵は `maximumAge:0` でも数秒前の fix を返すことがある）。
区間の突き合わせは両者が共通に持つ `recvAt` で行い、`t` とのズレは
`clockOffsetMs` / `deviceLagMs` として別に残す。

`overlap.deviceInRecording` は**記録区間**を基準に数える。受信機の最初のエポックは
複数センテンスが揃うまで確定せず1秒強かかるため、`gnss` の範囲で数えると
記録開始直後に届いた内蔵のサンプルを取りこぼす。また、静止中は OS が更新を間引いて
内蔵が1〜数点しか来ないことがあり、割合（`coverDevice`）だけでは対応を判断できない。

地点番号 `pointNo` は同じ `surveyId` の中の連番で、**欠番は再利用しない**（最大値＋1）。
一度出した対応表と番号がずれないようにするため。

### 生NMEA行の保存

設定 `saveRawNmea`（既定 ON）のとき、受信した行を `chunks[].rawNmea = [{ t, line }]` に
そのまま残す。パースを通す前に分岐させるので、チェックサムNG行や `$PPICO` も含まれる
（「受信したそのまま」を残す意味）。後から RTKLIB などの別ツールで再解析できる。

容量は 1Hz・10〜20行/秒で 1地点（30〜180秒）あたり 40〜250KB、20地点/日で 3〜5MB 程度。
上限 20000 行（`MAX_RAW_LINES`）を超えたぶんは捨て、本数を `summary.rawTruncated` に残して
記録が途中までであることを隠さない。

### v3 / v4 での作り直し

バージョンを上げるたびに既存ストアを全部 `deleteObjectStore` して作り直す。開発中のデータしか
無いため、**移行コードを持たないほうが結果的に安全で簡単**という判断。これにより
v1 → v2 の移行処理（`migrateToV2`）と、旧形式（`point` に配列を直接持つ）のフォールバック
分岐を持たずに済む。全レコードが `status` を持つ前提にもできる。

旧版を開いたままのタブがあるとアップグレードはブロックされる。**既にデプロイ済みの v2 の
コードには `onversionchange` が無いため、これは避けられない。** `onblocked` で
「他のタブを閉じて再読込」を案内する。今後のアップグレードのために `db.onversionchange`
で自分の接続を閉じるようにした。

### Android内蔵GNSS の並行取得（比較データ）

`deviceSamples` / `deviceStats` / `summary.deviceDrms` は **並行取得した記録にだけ足す**
（取得していない記録の形は従来のまま＝後方互換。取込側も任意扱いで読む）。

- `deviceStats` は `computeDeviceStats()` の戻り値 ＝ `computeStaticStats()` の全項目 ＋
  `avgAccuracy` / `dupCount` / `offsetFromRef {e, n, distM, bearingDeg}`。
  ばらつきの定義を受信機側と共有するため、集計本体は `computeStaticStats` をそのまま使う。
- `offsetFromRef` の基準は **GNSS受信機の中心**。散布図で共通原点に重ねる際の平行移動量
  そのものなので、描画側は差分を再計算せず `offsetFromRef.e / .n` を足すだけでよい。
- `dupCount`（直前と完全同一座標の点数）は保存後・取込後も再計算できるよう
  サンプル列から算出する（フラグとしてサンプルに持たせない）。

### エクスポート / インポート

**出力は ZIP 1ファイルに集約**する（形式ごとのボタンは持たない。11. 参照）。
`file-io.js` は「文字列を組み立てる」ところまでを担い、どのファイルをどう束ねるかは
`package-io.js` が決める。

地点ごとのファイル（`file-io.js` の `build*`）:

- `epochs.csv`: 1行1エポック。列に `snr_avg_used_dbhz`（使用衛星の平均 C/N0）と `recv_at_local` を持つ。
  末尾に地点の識別（`survey_id` / `point_no`）と集計値をコメント行で付ける。
  Android内蔵は行として混ぜず、`# device_*` のコメント行で比較値のみ出す。
- `device.csv`: 1行1サンプル（Android内蔵）。測位確定時刻・受信時刻・`fix_lag_ms` を持つ。
- `track.gpx`: 記録の中心を `wpt`、生エポック群を `trk` として出力（GNSS受信機のみ）。
- `raw.nmea`: `point.rawNmea` の行をそのまま出力（**無加工**。コメント行も入れない）。
- `raw_index.csv`: エポック ↔ `raw.nmea` の行番号（`buildRawIndex`）。
- `point.json`: `{ app:'gnss-scope', format:1, exportedAt, session, point, rawNmeaFile }`。
  生NMEA は `raw.nmea` にあるので `point` からは外す（同じデータを二重に持たない）。

調査日ごとのファイル:

- `compare.csv`: **1行1地点**で2系統を横並びにした表（`compareRow` / `COMPARE_HEADER`）。
  列名の接頭辞 `gnss_*` / `dev_*` が系統を表す（機種名は入れない）。
  先頭2列が `survey_id` / `point_no` で、これが地点の対応そのもの。
  ばらつき（DRMS / CEP / 標準偏差）に加え、`center_offset_m`・`drms_ratio_dev_over_gnss`、
  対応の検証列（`overlap_s` / `cover_*_pct` / `dev_in_record_window` / `clock_offset_ms` / `dev_fix_lag_ms`）を持つ。
  2系統比較の入口はこのファイル。
- `survey.json`: 調査日メタ＋全地点のメタと集計値（実データなし）。中身を開かずに内容を知るため。
- `manifest.json`: 出力の索引（`format:3`）。地点 → ディレクトリ・ファイル名・件数の対応表。

取込は入口が2つ。`importSessionFile`（JSON。単体 format 1・バンドル format 2）と
`importPackageFile`（出力ZIP format 3）で、どちらも `{ entries, skipped }` を返し、
1地点ぶんの書き込みは `importPointData` に1本化してある。
**既に持っている地点（`findSamePoint`）は書かずに `null` を返す**ので、重複判定も1か所で済む。取込時は **必ず新 id を採番**し
（同じファイルの二重取込でも上書きしない）、元 id は `sourceId`、元の地点番号は `sourcePointNo` に残す。
調査日は元データの日付をそのまま使い（同じ日の測定は同じ調査日に集まる方が突き合わせやすい）、
地点番号だけ取込先で採り直す。`stats` が欠けている JSON は `computeStaticStats` で再計算する。
**写真の枚数・バイト数は取込先で数え直す**（元データの値を持ち込むと、写真が無いのに `📷` が付く）。

## 5. 解析タブ

| 表示 | ライブ | 読込データ |
|---|---|---|
| SkyPlot / SNR | 最新エポック | スライダで選んだエポック（保存済み衛星リストから再現） |
| DOP（バー＋数値・測位モード・衛星数・精度ソース・GST σ） | 最新エポック | 同上 |
| DRMS（散布図＋集計テキスト） | 記録中／直近の記録の暫定集計 | 読込データの確定集計 |
| DRMS の比較系列（Android内蔵） | 同区間の暫定集計（記録中から見える） | `point.deviceStats` |

- レイアウトは 2 列グリッド（`.an-grid`）。上段 SkyPlot / DRMS、下段 SNR / DOP。
  見出し（`.sub-head`）と本体（`.an-cell`）を別セルにして、見出しの行数が違っても左右の図の上端が揃うようにしている。
  行数の多い DRMS 集計テキストは `.an-wide` で 2 列ぶち抜き。
  列幅に追従させるため `grid-template-columns` は `minmax(0, 1fr)`（canvas の内在サイズに列幅を引っ張られないように）。
- ソースはラジオで切替。読込データが無い間は「読込データ」を `disabled` にする。
- 保存サンプル → 表示用エポックへの変換（`sampleToEpoch`）で `recvAt` を補い、
  `canvas-view.js` のキャリーフォワード判定（`holdDecision`）がライブと同じ経路で働くようにしている。
- 系統別内訳は、ライブでは GSA 由来の `usedBySys` / `inViewBySys` を使い、
  無い場合（読込データ）は衛星リストから数える。
- 比較系列は `ScatterPlotView.update(stats, deviceStats)` の第2引数で渡す。
  基底クラスのリサイズ再描画は `update(this._last)` と1引数で呼ぶため、第2引数の既定値を
  **保持中の系列（`this._lastDevice`）** にしてある（比較を消すときは明示的に `null` を渡す）。
- `update()` は表示範囲の外に出た点数 `{ gnss, device }` を返す。呼び出し側（記録タブ・解析タブ）が
  「表示範囲の外側に N 点」を凡例の下に出す（`algospec-202609.md` 6-4）。
- 表示半径はヒステリシス付きでビューが保持する。**別のデータへ切り替えるときは
  `resetScale()` を呼ぶ**（記録開始時、解析タブのソース切替時・`setLoaded` 時）。
  呼ばないと前の記録のスケールを引きずる。
- 統計円のラベルは**種別のみ**（`CEP50` / `DRMS`）で、系統は色で表す。象限を分けて描くのは、
  比較系列を重ねるとスケールが大きい方に引かれ、受信機側の円が小さくなってラベルが
  中心で潰れるため。中心からの距離にも下限（10 px）を設けている。
- 系統は色だけでなく**形**でも分ける（塗り＝GNSS受信機 / 中抜き＝Android内蔵）。
  屋外の直射日光下と色覚特性の両方で、色だけの区別は落ちるため。凡例の記号も同じ規則。

## 6. モジュール構成

  `getPendingId()` / `onPendingGone()` の 2 本だけで触る（この 2 本は生成順の都合で遅延参照）。
- `device-gnss.js` は「受信経路」であってライフサイクルを持たないため、開始/停止は
  `Recorder` が握る（記録区間＝取得区間を自明にする）。`app.js` は
  `onSample → recorder.addDeviceSample` を結線するだけ。状態（許可待ち・拒否など）は
  `deviceGnss.status` を記録タブの凡例が読みに行く（通知は持たない）。
- `nmea.js` は他モジュールへ依存しない（受信経路の最下層）。
- **画面に出る系統名は `constants.js` の `SERIES` だけから引く。**
  受信機の機種を替えたときに追従漏れが起きないようにするため、各モジュールに
  ラベルを直書きしない（テスト側も `SERIES` を参照する）。
- 廃止：旧「ライブ」タブ（記録タブの「現在の測位値」へ統合）／旧「情報」タブ（設定タブへ統合）／
  スナップショット記録／記録の一時停止（打ち切りはデータ途絶で判定。3. 参照）。

## 7. PWA・オフラインタイル

- 版数は `sw.js` の `APP_VERSION`（`'yyyy-mm-dd.n'` = 更新日 ＋ 同日内の連番。日付が変われば 1 に戻す）。
  シェルキャッシュ名は `gnss-scope-shell-${APP_VERSION}`（接頭辞は `activate` の掃除で
  他キャッシュと区別するためのもの）。`settings-ui.js` は `APP_VERSION` を正規表現で読み取り、
  接頭辞なしの版数で表示・比較する（旧SWがキャッシュ名を返す場合は接頭辞を外す）。
  `APP_SHELL` には全モジュールを列挙する。
- 地理院タイルは cache-first でキャッシュ `gsi-tiles` に格納する。Service Worker（実行時の
  取得）と事前ダウンロード（`map.js` の `TileCache`）が**同じキャッシュ名を共有**する点が要。
- 未キャッシュのタイルをオフラインで要求した場合は 504 を返し、Leaflet 側でグレー表示にする。

### タイルマニフェスト（`data/tile_manifest.json`）

事前ダウンロードの対象を座標リストで持つ（Format A）。マニフェストは `data/` を唯一の置き場とし、
ルート直下に複製を置かない。

```json
{
  "version": "2026-06-01",
  "layers": {
    "<任意のキー>": { "z": 17, "tiles": [[x, y], [x, y], ...] }
  }
}
```

- `z` はズームレベル、`tiles` は当該ズームのタイル座標 `[x, y]` の配列。
- URL は選択中の地図種別のテンプレート（`GSI_LAYERS[mapType].url`）の `{z}/{x}/{y}` を置換して生成する。
  したがって**地図種別を変えると、その種別のタイルは再取得が必要**。
- `version` は取得時に `settings.tileCacheMeta` へ記録し、オフラインでも取得済み内容を表示できるようにする。

## 11. 一覧タブと出力ZIP（202608）

保存した記録の一覧を記録タブから切り出し、「一覧」タブにした。出力は形式ごとのボタンを廃し、
**ZIP 1ファイル**に集約した（機能まとめは `list-202609.md`）。

### なぜ画面を分けたか

記録タブは「測っている最中に見る画面」で、一覧は「後から整理する画面」。滞在する場面が
まったく違うのに 1 枚に載せていたため、測定中に不要な情報が下半分を占めていた。
容量の警告も一覧側へ移した（警告を解決する手段＝出力と削除がそこにあるため）。

### なぜ ZIP か

「生NMEA を加工せずに、測位結果と紐付けたまま持ち出す」が要件だった。JSON 1ファイルに
まとめると生NMEA が文字列としてエスケープされ、RTKLIB など別ツールへ渡すのに一手間かかる。
個別ダウンロードの連発は Android Chrome が複数DLの許可を求めるうえ、紐付けがファイル名だけに
なる。ZIP ならディレクトリで対応を表せて、`raw.nmea` を無加工のまま置ける。

外部ライブラリを入れない方針のため `zip.js` を自前で持つ（ローカルヘッダ＋セントラル
ディレクトリ＋CRC-32。ZIP64・暗号化・分割は実装しない）。圧縮は `CompressionStream('deflate-raw')`
に任せ、非対応の環境では無圧縮（store）へ落ちる。`zip.js` は DOM に触らないので
Node 側のテストから往復（`zipEncode` → `zipDecode`）を確かめられる。

### 対応をどう保証するか

`raw.nmea` を無加工にした以上、ファイルの中身だけでは地点が分からない。そこで紐付けを
3重にした（パス／中身の `survey_id`+`point_no`／`manifest.json` の索引）。どれか1つが
崩れても辿れる。

エポックと生行の対応は `raw_index.csv` で持つ。エポックの `recvAt` は「そのエポックの最初の
センテンスを受け取った時刻」なので `[recvAt_k, recvAt_{k+1})` で区切れるが、
**保存時にエポック境界そのものは持っていない**ため、これは受信時刻からの再構成（近似）である。
行が0のエポックも1行として残し、生行が落ちた区間が読み取れるようにした。

### メモリの扱い

20地点ぶんの実データ（生NMEA 3〜5MB ＋ 写真 20MB）を一度に並べると端末にはつらい。
`zipEncode` は同期・非同期どちらの反復可能オブジェクトも受けるようにし、`package-io.js` は
**地点ごとに読んで詰め終わったら手放す** async generator でエントリを渡す。
`manifest.json` は件数が確定してから書くので最後に詰める（読む側はセントラルディレクトリから引く）。

### モジュールの移動

`session-list-ui.js` は `list-ui.js` へ改名した（タブ単位で並ぶ `*-ui.js` の命名に揃えるため）。
`file-io.js` は出力の実体（`download`）から切り離し、`build*` が文字列を返す形にした。

### 重複を端末内に持たない

取込は「追加」なので、同じファイルを2回読めばそのぶん増えてしまう。照合キーは
**調査日 ＋ 記録開始時刻[ms]**（`findSamePoint`。`survey.js`）にした。

- id では照合できない。取込のたびに `imp_<ms>_<調査日>_<地点番号>` を採り直すため、
  A → B → A と往復させると別物になる。`sourceId` も 1 段しか遡れない。
- 記録開始時刻（`session.createdAt`）は取込でも書き出しでも元の値のまま持ち回るので、
  往復しても一致する。同じ端末で同じミリ秒に 2 つの記録は始められないため、実質一意。
- 判定は `importPointData` の書き込み直前で行う。1 つのファイルに同じ地点が 2 つ入っていても、
  2 件目は既に書いた 1 件目と照合されて弾かれる。
- 下書きとも照合する（同じ測定を下書きで持っているなら、取り込めば二重になる）。
- ZIP ではスキップした地点の写真も足さない（同じ地点に写真だけ増えるのを防ぐ）。

置き換え（既存を消して入れ直す）は選べるようにしていない。取込は「増やす」操作に留め、
消すのは削除の操作（下記）で明示的に行う。

### 端末内のデータを全消去

日単位の削除（一覧タブ）の上位として、設定タブに `端末内のデータを全消去` を置いた。

- `storage.clearRecords()` は記録の 5 ストアを **1 トランザクションで `clear()`** する。
  `indexedDB.deleteDatabase()` は使わない（他タブに開かれていると `onblocked` で止まり、
  スキーマも作り直すことになる）。
- `settings`（`tileCacheMeta`）と地図タイル（Cache Storage）は消さない。タイルは記録データとは
  別の持ち物で、消すと再ダウンロードが重い。
- 確認は 1 回目に失うものを数えて見せ（`getStorageUsage()` に件数を足した）、
  **未書き出しがあるときだけ** 2 回目で止める。常に 2 回にすると確認が読まれなくなる。
- 記録中は実行しない。消した後は `onRecordsCleared` で読込データと未確定の記録を手放してから
  一覧と容量表示を作り直す（消えたものを指したままにしない）。

### 一覧は session だけで描く

行に出す値（2系統の DRMS・中心のズレ・NMEA の量・区間の重なり）は `session.summary` と
`session.window` から作る。実データを結合するのは「読込」「出力」のときだけ。
このために `buildSummary` へ `deviceOffsetM` / `deviceOffsetDeg` を足した
（この項目を持たない古い記録では中心のズレを出さない）。

## 12. 一覧を日ごとに畳む（202609）

一覧タブから**確定した地点の行を外し**、調査日の行だけにした。1地点ずつ見る操作は
解析タブ・地図タブの**地点セレクタ**（`loaded-picker.js`）へ移した。
保存するデータの形は変えていない（一覧に出さないだけで、`session` / `point` はそのまま）。

### なぜ畳んだか

持ち出し（📦 出力）も片付け（日ごと削除）も**日単位**の操作なのに、その判断材料である
日の集計が 20 地点ぶんの行に埋もれていた。1日20地点×数日を並べても「どの日が片付いて
いないか」は読み取れない。行を畳んで、日の見出しに `書出済` / `下書き n件` / `⚠ n地点` /
`読込中 No.x` を集約した。

`⚠` は畳んだぶん**日ごとの件数**に変えた（`lossWarnText` はそのまま使い、地点ごとの内訳は
ツールチップへ）。再測が要る日をこの画面で拾える、という元の役割は残す。

### 地点セレクタを両タブに置く

一覧が日までしか並べないため、地点を選ぶ場所が要る。解析タブ・地図タブの**両方**に
同じ `<select>` を出し、`loaded-picker.js` が 1 か所で面倒を見る。

- **どちらで切り替えても読込データそのものが入れ替わる**（見た目だけの切り替えにしない）。
  差し替えは `list-ui.js` の `loadSession(id)` に任せ、読込データを作る経路を 1 本に保つ。
- 下書きを読み込んでいるときは、その下書きをセレクタの先頭に足す。一覧に無いものを
  選択状態にできないと「今どれを見ているのか」が消えるため。
- 選択肢が 1 つの日では出さない。

### 取込が `surveyId` を返す

取込（`importSessionFile` / `importPackageFile`）の戻り値に `surveyId` を足した。
**すべて重複でスキップした場合でも、その日を開けるようにするため**。地点の行が無くなった
以上、「手元にあるのに読めない」行き止まりを作らない。書き込みの有無と、どの日だったかは
別の情報なので、`importSurveyId()` を `file-io.js` に切り出して両方から使う。

### 落とした機能

| 機能 | 判断 |
|---|---|
| 地点の「編集」（地点名・メモ・写真の後追い） | 代替なし。写真は保存フォーム（save の前）だけになった |
| 地点の「詳細」 | 読み込めば解析タブの DRMS 欄に同じ全文が出る（メモは出ない） |
