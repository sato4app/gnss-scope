# GNSS Scope 機能仕様書（202607）

本アプリが「何をするか」を定めた仕様書。操作手順は `usersGuide-202607.md`、
実装構成は `design-202607.md`、機器・ファームは `hardware-202607.md`、
判定式・算出式は `algospec-202607.md` を参照。

## 1. 目的と範囲

Pico W + u-blox MAX-M10S が BLE で流す**生 NMEA** を受信し、
**GNSS の測位品質を観測・記録・解析する**ための PWA。

| 項目 | 内容 |
|---|---|
| 主目的 | 静止点での測位のばらつき（DRMS / CEP）と衛星受信状況（SkyPlot / SNR / DOP）の評価 |
| 対象端末 | Android の Chrome / Edge（Web Bluetooth 必須）。iPhone / iPad は対象外 |
| 提供形態 | PWA（HTTPS または localhost 配信。ホーム画面へ追加可・オフライン動作） |
| データ保存 | 端末内の IndexedDB のみ（DB 名 `gnssScopeDB`）。外部送信は一切行わない |
| 対象外 | 移動ログ（軌跡）を主目的とした記録、ナビゲーション（経路案内）、複数端末間の同期 |

### 1-1. 2 系統の呼び方（画面・出力の用語）

受信機は将来入れ替える可能性があるため、**画面と出力には機種名を出さない**。
2 系統は次の名前で呼び、この 2 語だけを使う。

| 系統 | 表示名 | 実体 |
|---|---|---|
| 外部受信機 | **GNSS受信機** | BLE で生 NMEA を送ってくる機器（現状は MAX-M10S + Pico W） |
| 端末側 | **Android内蔵** | 端末自身の測位（Geolocation API / Fused Location） |

- 表示名の実体は `js/constants.js` の `SERIES` が唯一の出所。機種を替えるときはここだけ直す。
- 「NMEA」は**受信機が送ってくるデータ形式**の名前であって系統名ではない。
  「生NMEA」「NMEAエクスポート」などデータを指す表記はそのまま使う。
- CSV の列名は `gnss_*` / `dev_*` で系統を表す（機種名は入れない）。

## 2. 画面構成

常設のステータスバー ＋ 5 タブ（排他・全画面切替）。

| 領域 | 表示・機能 |
|---|---|
| ステータスバー | 接続状態ドット／接続状態ラベル／記録中インジケータ（`● REC` 点滅）／測位状態バッジ／最終受信からの経過秒 |
| 接続タブ | connect / disconnect、接続情報、受信品質統計 |
| 記録タブ | record / stop / save / load、収束の進捗バー、現在の測位値（折りたたみ）、散布図と 2 系統の凡例、測位結果（折りたたみ）、記録一覧 |
| 解析タブ | SkyPlot / SNR / DOP / DRMS（ライブ ↔ 読込データ切替） |
| 地図タブ | 地理院地図、読込データのマーカー表示、ライブ現在地表示 |
| 設定タブ | 測位・記録パラメータ、地図、オフラインタイル、アプリ更新、開発用モック |

測位状態バッジは GGA の fix quality と GSA の測位モードから決める。

| 条件 | 表示 |
|---|---|
| quality なし / 0 | `No fix`（赤） |
| quality 1 ＋ 2D | `2D`（橙） |
| quality 1 ＋ 3D | `3D`（青） |
| quality 2 / 4 / 5 / 6 | `DGPS` / `RTK Fixed`（緑） / `RTK Float`（橙） / `推測航法`（橙） |

## 3. 接続機能

### 3-1. connect / disconnect

- **connect**: BLE のデバイス選択ダイアログを開き、広告名 `picow` の機器へ接続する。
  ユーザー操作（ボタン押下）内でのみ実行する。
- **disconnect**: 手動切断。以後の自動再接続は行わない。モック配信中は配信を停止する。
- 接続開始時と切断時に、組み立て中のエポックを確定（フラッシュ）する。
- **自動再接続**: 意図しない切断（`gattserverdisconnected`）では指数バックオフで再接続を試みる
  （初回 500 ms → 倍々 → 上限 15 秒）。手動切断とは区別する。
- 接続を開始すると受信品質統計をリセットする（= 1 回の測定区間の起点）。

### 3-2. 接続状態

| 状態 | 表示 | 意味 |
|---|---|---|
| disconnected | 未接続 | 未接続・手動切断後 |
| connecting | 接続処理中… | デバイス選択／GATT 接続中 |
| connected | 接続中 | 接続済みだがデータが 3 秒以上来ていない |
| receiving | 受信中 | 最終受信から 3 秒以内 |
| reconnecting | 再接続中… | 自動再接続の待機・再試行中 |
| demo | モック配信中 | 開発用の擬似 NMEA を配信中 |
| unsupported | BLE非対応 | Web Bluetooth 非対応、または HTTPS でない |

BLE が使えない場合は理由（HTTPS 必須／端末非対応）を提示し、モック配信を案内する。

### 3-3. 受信品質統計

受信機 → Pico → BLE → アプリの各段で NMEA を取りこぼしていないかを、
接続（またはリセット）からの累計で表示する。算出方法は `algospec-202607.md` 5. 参照。

| 表示項目 | 内容 |
|---|---|
| 受信行数 / CS NG | 復元した行数 / うちチェックサム不一致（破棄） |
| 未対応文 / 破棄文字 | 検証は通ったが解釈対象外の文 / 行にならず破棄した文字数 |
| エポック / 欠落 | 確定エポック数 / 時刻ギャップから推定した欠落エポック数 |
| GSV部分欠落 | 分割 GSV のうち届かなかったメッセージ数 |
| BLE欠落（推定） | Pico の送信行数と本アプリの受信行数の差 |
| Pico統計 $PPICO | 最新の統計文の通し番号と、統計文自体の欠落数 |
| Pico UART受信 / NG | Pico が受信機から受けた行数 / うちチェックサム不一致 |
| Pico破棄 バッファ/BLE | Pico のバッファ破棄回数 / BLE 送信を諦めた行数 |

「統計リセット」で累計を 0 に戻す。チェックサム不一致行・未対応文は**件数を数えて破棄**し、
接続は維持する（エラーで停止しない）。

## 4. 記録機能

1 回の記録 = 1 地点。静止点に留まって連続エポックを収集し、ばらつきを集計する。

### 4-1. 状態遷移

```
待機 ──[record]──> 収集中 ──[stop / 自動停止]──> 下書き ──[save]──> 地点（＝読込データ）
                      │                          │
                 5秒ごとに追記                 [破棄]──> 削除
```

- **record**: **下書きを作ってから**収集を開始する。有効な測位値がない場合は開始せず警告する。
  下書きを作れなかった場合は記録しない（残せない記録は始めない）。開始時に Wake Lock を取得する。
- **収集中**: 5 エポック（≒5 秒）ごとに実データを下書きへ追記する。
  **保存を押す前にアプリが終了しても、直近の追記までは残る。**
- **stop**: 収集を停止し集計する。集計値も下書きへ書く。**まだ地点ではない**。
- **save**: 地点名とメモを付けて確定する。**このとき初めて地点番号を採番する。**
  そのまま読込データにする。
- **破棄**: 下書きと実データをまとめて削除する。
- **load**: 一覧から選ぶ、または JSON ファイルを取り込む。

**下書き**は「停止したがまだ地点になっていない記録」で、地点番号を持たない。
調査日の集計・対応表CSV・バンドルJSON の対象にもならない。測り直した失敗記録で
地点番号が飛ばないようにするため（4-6）。

### 4-2. 収集の条件

- 蓄積対象は「緯度経度があり、fix quality > 0」のエポックのみ。
- **最後のエポックから 10 秒が過ぎたら、記録を打ち切る（データ途絶）。**
  画面 OFF・他アプリへの切替・BLE 切断・受信機の電池切れ・fix 喪失を**一様に**拾う。
  データが届かないまま続けると、穴の空いた区間が 1 地点として残ってしまうため。
- 記録は**記録専用の端末**で行う前提とする。記録中に地図・写真・他アプリを見たい場合は
  別のスマートフォンを用意する。
- 判定を「画面が隠れたか」ではなく「データが来ているか」にしているのは、
  停止条件（収束・上限時間・上限エポック）の判定がエポック到着時にしか走らないため。
  エポックが途絶えるとそれらが評価されず、記録が止まらないまま残ってしまう。
- 10 秒にしているのは、BLE の瞬断が自動再接続で復帰するまでの猶予。

### 4-3. 停止条件

| 停止理由 | 条件 |
|---|---|
| 収束 | 自動停止 ON かつ 最低収集時間経過後に中心・DRMS が 10 秒横ばい |
| 上限時間到達 | 経過時間 ≥ 上限時間（0 は無効） |
| 上限エポック到達 | 収集点数 ≥ 上限エポック数（0 は無効） |
| 手動停止 | stop 押下 |
| データ途絶 | 最後のエポックから 10 秒（4-2） |
| 保存失敗 | 記録中の追記が続けて 3 回失敗した |

最低収集時間に達するまでは収束による停止を行わない。判定式は `algospec-202607.md` 3. 参照。

**停止の知らせ方**（画面を見ていなくても分かるようにする）

| 停止理由 | ビープ音 | 測位結果の見出し |
|---|---|---|
| 収束 | 短く 2 回（高め） | `収束で自動停止（45秒/45点）` |
| 上限時間到達 | 長く 1 回（低め） | `上限時間で停止（未収束: 180秒/180点）` |
| 上限エポック到達 | 長く 1 回（低め） | `上限エポックで停止（未収束: 150秒/300点）` |
| 手動停止 | 鳴らさない | `手動停止（未収束: 20秒/20点）` |
| データ途絶 | 長く 1 回（低め） | `データ途絶で停止（未収束: 45秒/40点）` |
| 保存失敗 | 長く 1 回（低め） | `保存失敗で停止（未収束: 60秒/58点）` |

- 手動停止で鳴らさないのは、操作した本人が停止を分かっているため。
  データ途絶・保存失敗は本人が停止を分かっていないので鳴らす。
  画面を見ずに「受信が切れた」と気付けるほうが現場では価値が大きい。

- 音のパターンで「良い結果で終わった（収束）」と「未収束のまま打ち切った」を区別できるので、
  画面を見ずに「移動してよいか／測り直すか」を判断できる。
- 自動停止が OFF のときは「未収束」ではなく `収束判定なし: ` と書く（判定していないため）。
- 有効なエポックが 1 点も無い場合は `測位データなしで停止（30秒/0点）`。
- 秒数と点数を併記するのは、1 Hz なら本来一致するはずの 2 つがずれていれば
  取りこぼし（BLE 欠落・途絶）があったと分かるため。
- ビープは設定「自動停止をビープ音で知らせる」（既定 ON）で切れる。端末が消音・音量 0 なら鳴らない。

**停止後の扱い**

- 有効エポックが 0 点なら、下書きごと削除する（復元しても使えないため）。
- **経過 30 秒以上で有効エポックが 10 点未満**なら、破棄するかを確認する。
  1 Hz なら 30 秒で 30 点が期待値で、10 点未満は取りこぼしが大きい。
  集計は 1 点でも計算できてしまうため、そのまま地点にすると
  DRMS がほぼ 0 という偽の「良い値」が残ってしまう。
  確認は結果を描画した後に出す。下書きは書けているので、答えないまま放置しても失われない。

### 4-4. 収集中の表示

**同じ値を 2 か所に出さない。** 置き場所は次の 1 か所ずつに決めている。

| 内容 | 置き場所 |
|---|---|
| 点数・実測秒数・DRMS（2 系統とも） | 散布図の下の凡例 |
| 経過時間・収束の進み具合 | 進捗バー |
| 停止した理由 | 測位結果の見出し（4-3） |
| それ以外の明細 | 測位結果を開いた中（集計値・2 系統の比較・測定区間） |

**進捗バー**（記録中のみ表示。判定の 2 フェーズは `algospec-202607.md` 3-3-1）

| バー | 内容 |
|---|---|
| 主バー「経過」 | 経過 / 上限時間。最低収集時間の位置にマーカーを立てる。上限時間が 0（無制限）なら経過秒のみ |
| 副バー フェーズ1「最低時間」 | 最低収集時間に届くまでの残り |
| 副バー フェーズ2「安定待ち」 | 品質の良いエポックが連続で溜まった秒数 / 10 秒。品質不良でリセットされると 0 に戻り、戻ったことが分かるよう色を変える |
| 副バー フェーズ3「判定中」 | 10 秒の窓が揃った後。中心移動・DRMS 幅の「実測値 / 許容値」をゲージで出し、許容内なら緑 |

窓が揃っても中心が動いていれば停止しないため、「安定待ち」と「判定中」を分けて表示する
（バーが満タンのまま止まらない状態を説明できるようにするため）。
自動停止が OFF のときは副バーを出さない。バーの脇に、収束判定の品質ゲート条件
（使用/視野内衛星数・HDOP・測位モード）を出し、止まらない理由の手掛かりにする。

**散布図の凡例**（2 系統を 1 行ずつ）

```
● GNSS受信機   45秒間 132点  DRMS 1.24m
◎ Android内蔵  45秒間  14点  DRMS 4.81m
```

- 記号は**色だけでなく形でも**区別する（塗り ● = GNSS受信機 / 中抜き ◎ = Android内蔵）。
  直射日光下や色覚特性では色が頼れないため。散布図の点の描き分けも同じ。
- 点数だけを並べると「内蔵は点が少ない＝劣る」と読めてしまう。受信機が 1 Hz なのに対し
  内蔵は OS が更新を間引くだけなので、**実測の秒数を併記**する。
- Android内蔵が 1 点も取れていないときは、点数の代わりに状態を出す
  （`— 取得OFF（設定で有効にできます）` / `— 未許可（端末の位置情報を許可してください）` /
  `— 測位できません` / `— この端末/ブラウザは非対応`）。
- 表示範囲の外に出た点があれば、凡例の下に系統別の件数を出す
  （`表示範囲の外側に GNSS受信機 2点 / Android内蔵 5点（▲は方向）`）。

**折りたたみ**

- 「現在の測位値」（緯度・経度・標高・推定水平精度・衛星数・HDOP）は、
  記録中は自動で畳んで進捗バーと散布図に画面を譲る。停止すると開く。
- 「測位結果」は見出しに停止条件だけを出し、明細は開いたときだけ見せる。
  開閉状態は保持する（一度開けば次の記録でも開いたまま）。
- 散布図と測位結果は、**最初の記録を始めるまで表示しない**（空の正方形で画面を埋めない）。

### 4-5. 集計値

停止時に次を算出する（定義は `algospec-202607.md` 2.）。

平均緯度経度（中心）／中央値／東西・南北の標準偏差 [m]／DRMS・2DRMS／CEP50・CEP95／
標高の平均・標準偏差／収集エポック数／fix 種別の内訳／平均 PDOP・HDOP・VDOP／平均衛星数／
使用衛星の平均 C/N0／中心からのオフセット（散布図用）／測定区間の受信品質。

### 4-6. 保存と一覧（調査日 → 地点のツリー）

1日に何十地点もまわる使い方を前提に、記録は **調査日 → 地点** の 2 階層で管理する。

- 保存（確定）時に、その日の中での**地点番号**（1 から始まる連番）を自動で採番する。
  地点名の既定値は `yyyy-mm-dd-xx`（xx = 地点番号 2 桁）。メモは任意。
  **調査日**（`yyyy-mm-dd`。端末のローカル日付）は記録開始の時点で決まる。
- **地点番号は確定済みの記録だけを見て採る。** 下書きは番号を消費しないので、
  測り直した失敗記録を捨てても番号が飛ばない。
- 地点番号は **欠番を再利用しない**（同じ調査日の最大値＋1）。一度出した対応表と番号がずれないため。
- 一覧では**下書きを調査日の先頭**にまとめて出す。行には `下書き` バッジと停止時刻を出し、
  操作は **保存 / 読込 / 削除** の 3 つだけ（エクスポートは確定してから）。
  「保存」を押すとその行に地点名・メモの入力欄が開き、確定できる。
  **アプリを再起動した後でも、ここから下書きを地点にできる。**
- 停止処理が走らないまま落ちた記録は `記録中に中断` と出る。集計値は読込・確定のときに作り直す。
- 調査日の見出しの地点数・平均DRMS・両系統カウントは**確定済みのみ**で数える。
  下書きがあれば `下書き n件` を併記する（保存漏れに気付けるようにするため）。
- **中身のある下書きは自動で消さない。** ただし起動時に、実データを 1 件も持たない下書き
  （最初の追記より前に落ちたもの）だけは片付ける。復元できるものが無いため。
- 1 地点の GNSS受信機と Android内蔵のデータは**同じレコード**に保存されるため、
  地点の対応が構造上ずれない。
  そのうえで、後から「本当に同じ時間に測ったか」を確認できるよう測定区間を残す（4-9）。
- 一覧は調査日ごとの折りたたみで表示する。
  - 調査日の見出し: 日付・地点数・2 系統が揃った地点数・平均 DRMS（GNSS受信機 / Android内蔵）
  - 調査日の操作: **対応表CSV** / **バンドルJSON** / **日ごと削除**（配下の地点もまとめて削除）
  - 地点の行: 地点番号・種別（記録／取込）・地点名・日時・点数・DRMS・中心座標に加え、
    2 系統の対応（GNSS受信機の点数 / 生NMEA 行数 / Android内蔵の点数 / 記録区間内の点数）
  - 地点の操作: **読込** / **CSV** / **GPX** / **NMEA** / **JSON** / **削除**（削除は確認あり）
    （NMEA は生NMEA が保存されている地点でのみ押せる）
- 読込中の記録を強調表示する。読込中の記録を削除した場合は、読込データを解除する。
- 調査日が空になったら、その調査日自体も片付ける。

### 4-7. 取込（JSON）

本アプリが出力した JSON を読み込み、この端末の一覧に追加する。単体（1 地点）と
調査日バンドル（その日の全地点）のどちらも同じボタンで読める。

- 検証: `session` / `point` / `point.samples`（1 件以上）の存在。不足時は、どの地点が
  不正かを添えてエラー表示。
- 取込のたびに新しい id を採番するため、同じファイルを 2 回読んでも上書きにならない。
  元の id は `sourceId`、元の地点番号は `sourcePointNo` として保持する。
- 調査日は元データの日付をそのまま使い（同じ日の測定は同じ調査日に集まる）、
  地点番号だけ取込先で採り直す。
- 集計値が欠けている場合は生エポックから再計算する。

### 4-8. Android内蔵GNSS の並行取得（比較）

**同じ区間・同じ場所で** 端末（スマートフォン）自身の測位も並行して収集し、
DRMS の比較対象にする。「外部の GNSS受信機はスマホ内蔵よりどれだけ良いのか」を、
時刻も場所も揃った条件で評価するための機能。

| 項目 | 仕様 |
|---|---|
| 取得区間 | 記録中（record 〜 stop）のみ。常時取得はしない |
| 取得手段 | ブラウザの Geolocation API（`watchPosition`、高精度モード） |
| 収集内容 | 時刻・緯度・経度・accuracy（68%円半径）・楕円体高・速度・進路 |
| 中断 | 記録が中断停止すれば内蔵側の収集も止まる（4-2。一時停止という状態は持たない） |
| 有効/無効 | 設定「記録中に Android内蔵GNSS も取得して比較する」（既定 ON） |
| 集計 | GNSS受信機と同じ定義（DRMS / CEP50 / CEP95 / 標準偏差）に加え、平均 accuracy・
座標重複数・GNSS受信機の中心からのズレ（距離と 16 方位） |

取得できない値（**衛星リスト・DOP・fix 種別・生 NMEA**）はブラウザからは取得手段がないため、
比較は「ばらつきの統計」同士に留め、エポック単位の 1 対 1 比較は行わない。

- **座標重複**：静止中は OS が測位更新を間引き、直前と同一の座標を返し続けることがある。
  これはばらつきを過小評価する（内蔵の方が優秀に見える）ため、重複した点数を必ず表示し、
  全体の 30% 以上を占める場合は注意文を添える。
- 内蔵側の値は GNSS 単独ではなく WiFi / 基地局を融合した測位（Fused Location）である旨を常に併記する。

### 4-9. 生NMEA の保存と、地点の対応の検証

**生NMEA の保存**（設定「生NMEA行もそのまま保存する」既定 ON）

受信した NMEA 行を、パースを通す前にそのまま記録へ残す。後から RTKLIB などの別ツールで
再解析するため。チェックサム NG 行・`$PPICO` も「受信したそのまま」として含める。

- 容量の目安: 1 地点（30〜180 秒）あたり 40〜250 KB、20 地点/日で 3〜5 MB 程度。
- 上限 20000 行を超えたぶんは保存せず、超過した行数を記録に残して途中までであることを示す。
- 地点ごとに `.nmea` テキストとして書き出せる（4-6）。

**測定区間（地点の対応の検証）**

停止時に、2 系統それぞれの測定区間と重なりを記録に残す。記録タブ・解析タブの集計テキストと、
調査日の対応表CSV に出す。

| 項目 | 意味 |
|---|---|
| GNSS受信機 の区間 | エポックが取れていた時刻範囲と点数 |
| Android内蔵 の区間 | 測位が取れていた時刻範囲と点数 |
| 重なり | 重なった秒数と、各区間に占める割合 |
| 記録区間内の点数 | Android内蔵のサンプルのうち record〜stop の間に受信した点数 |
| 端末時計 − GPS時刻 | 2 系統を同じ時間軸へ並べ直すときの補正量 |
| Android内蔵 の測位の古さ | 受信時刻 − OS が測位を確定した時刻 |

時刻の扱いに注意が要る。受信機の時刻は GPS 時刻、内蔵の時刻は OS が測位を確定した
時刻であり、**別の時計**である（`maximumAge` を 0 にしても数秒前に確定した測位が返ることがある）。
区間の突き合わせは両者に共通する「アプリが受信した時刻」で行い、上記 2 項目でズレを示す。

「記録区間内の点数」を割合と別に持つのは、静止中に OS が更新を間引いて内蔵が
1〜数点しか返さない場合、割合だけでは対応を判断できないため。

## 5. 解析機能

データソースをラジオで切り替える。読込データが無い間は「読込データ」を選択できない。

| ソース | 対象 |
|---|---|
| ライブ | 受信中の最新エポック（1 エポックごとに更新） |
| 読込データ | load した記録。スライダで任意のエポックを選んで再現する |

記録時に**各エポックの衛星リスト（系統 / PRN / 仰角 / 方位 / C/N0 / 使用中）も保存**するため、
保存後・取込後でも SkyPlot と SNR を再現できる。

画面は 2 列に並べる。上段が SkyPlot（左）と DRMS 散布図（右）、下段が SNR（左）と DOP（右）で、
DRMS の集計テキストと測位モード等の数値は 2 列ぶち抜きで表示する。
図は列幅に合わせて伸縮し、SkyPlot は表示が小さいとき（幅 240 px 未満）PRN ラベルを省く。

### 5-1. SkyPlot（スカイプロット）

| 要素 | 表現 |
|---|---|
| 半径 | 仰角（中心 = 90°、外周 = 0°）。仰角リングは 0 / 30 / 60° |
| 角度 | 方位角（真上 = 北、時計回り）。N / S / E / W ラベル |
| 円の大きさ | C/N0（大きいほど強い） |
| 塗り | 測位に使用中 = 塗りつぶし、可視のみ = 中抜き |
| 色 | コンステレーション（GPS / GLONASS / Galileo / BeiDou / QZSS） |
| 数字 | PRN（衛星番号） |

### 5-2. SNR（C/N0）チャート

- 可視衛星ごとに 1 本の棒。縦軸は 0〜55 dBHz（目盛 0 / 20 / 40）。
- 色はコンステレーション、使用中は濃く・可視のみは薄く表示する。
- 並び順はコンステレーション順 → PRN 順。

### 5-3. DOP

PDOP / HDOP / VDOP を数値とバーで表示する。バーは 6 以上で満タン、
色は 2 未満で緑、4 未満で橙、それ以上で赤。あわせて測位モード・使用/視野内衛星数・
精度ソース（GST または HDOP×UERE と推定値）・GST の緯度経度標準偏差を表示する。

### 5-4. DRMS

散布図（中心からの東西 × 南北オフセット [m]）と集計テキストを表示する。

- 散布図には CEP50（緑・破線）と DRMS（青・破線）の円、各エポックの点、中心を描く。
- 目盛りリングは 1 / 2 / 5 × 10ⁿ の間隔に丸め、**表示半径より外には描かない**
  （表示半径は範囲外判定の境界なので、その外にリングがあると誤解を招く）。
- ソースがライブのときは「記録中／直近の記録」の暫定集計を表示し、
  記録がまだ無ければ案内文を表示する。

#### 表示半径（スケール）

表示半径 R は次で決める（算出は `algospec-202607.md` 6.）。

```
R = max(2 m, GNSS受信機のDRMS × 4, Android内蔵のDRMS × 2)  → 段階へ切り上げ
```

- **点の最大半径ではなく DRMS を基準にする。** 最大半径で決めると、内蔵の外れ点 1 つで
  受信機の点群が中心の数ピクセルへ潰れてしまう。DRMS は外れ値に強い。
- 下限 2 m は、記録開始直後（DRMS ≒ 0）にスケールが極端に小さくなるのを防ぐため。
- 記録中に毎秒スケールが動かないよう、段階へ切り上げたうえで**ヒステリシス**をかける
  （拡大は即座に、縮小は目標が現在の半分を下回るまで待つ）。
- **表示範囲の外に出た点は縁に▲でクランプ**して描き、系統別の件数を凡例の下に出す（4-4）。
  件数だけでなく方向も残るので、内蔵の中心が大きくずれている場合でもどちらへ飛んだか読める。
- 内蔵の中心そのものが表示範囲の外にある場合は、内蔵の中心マーカーと DRMS 円は描かない
  （点は▲として縁に出る）。中心のズレの数値は集計テキストで読む。

#### Android内蔵GNSS との比較

4-8 の並行取得データがある記録では、「Android内蔵と比較」チェックボックス（既定 ON）で
同じ散布図に 2 系統目を重ねる。比較データが無い記録ではチェックボックス自体を出さない。

- **原点は GNSS受信機の中心に揃える**。内蔵側の点は中心のズレぶんだけ平行移動して描くため、
  ばらつきの大小に加えて「2 つがどれだけ違う場所を指しているか」も同時に読める。
  このズレは受信機の中心からの相対値であり、真位置からの誤差ではない。
- 色と形で系統を、円のラベルで種別を表す。
  - GNSS受信機: 橙・**塗りの点**、CEP50 円（緑）・DRMS 円（青）
  - Android内蔵: 紫・**中抜きの点**、DRMS 円（紫）
  - 円のラベルは `CEP50` / `DRMS` の種別のみ（系統は色で分かる）。向きを散らして重ならないようにする。
- 集計テキストには DRMS / CEP50 / CEP95 / 標準偏差を 2 系統並べ、倍率・中心のズレ・
  平均 accuracy・座標重複数・Fused Location の注記を添える。

### 5-5. 衛星表示の保持

GSV が届かない秒に表示が点滅しないよう、直前フレームを保持する。
最後に衛星データを描画してから 8 秒を超えた場合は枠のみを残してクリアする
（判定は `algospec-202607.md` 4.）。

## 6. 地図機能

地図は主役ではなく 1 タブ。主な役目は **load した記録の GNSS 値の表示**。

| 表示 | 内容 |
|---|---|
| 背景地図 | 地理院地図（標準 / 淡色 / 写真）。初期中心は箕面大滝、既定ズーム z=17 |
| 読込データ | 各エポックの点群（橙）＋中心マーカー（緑・ポップアップに地点名/座標/DRMS）＋ DRMS 円 |
| ライブ | 現在地マーカー・推定水平精度の円・軌跡（設定で ON/OFF） |
| 操作 | 「追従」トグル（地図を手で動かすと自動解除）／「読込データへ」で読込範囲へフィット（最大 z=17） |
| 情報表示 | 読込中の地点名・点数・DRMS |

読込データを設定した時、および地図タブを開いた時に読込範囲へフィットする。

## 7. 設定

| 設定 | 既定値 | 範囲・意味 |
|---|---|---|
| UERE | 5 m | 1〜30。GST が無い場合の水平精度概算（HDOP × UERE）に用いる |
| 収束で自動停止 | ON | 中心・DRMS が 10 秒横ばいになったら記録を自動停止する |
| 自動停止をビープ音で知らせる | ON | 収束は短く 2 回、上限時間・上限エポックは長く 1 回（4-3）。手動停止・中断では鳴らさない |
| 記録中に Android内蔵GNSS も取得して比較する | ON | 記録中だけ端末自身の測位も収集し、DRMS を比較する（4-8） |
| 生NMEA行もそのまま保存する | ON | 受信した NMEA 行を記録に残す。別ツールでの再解析用（4-9） |
| 記録 最低収集時間 | 30 秒 | これ未満では収束による停止を行わない |
| 記録 上限時間 | 180 秒 | 0 = 無制限。未収束時のタイムアウト |
| 記録 収集エポック数 | 300 | 0 = 無制限 |
| 地図種別 | 標準 | 標準 / 淡色 / 写真 |
| ライブ軌跡を表示 | ON | OFF にすると既存の軌跡も消える |
| モックNMEA配信 | OFF | 実機なしで 5 系統フル GSV の擬似 NMEA を 1 Hz 配信（開発用） |

**設定値は永続化しない。** 既定値は `js/constants.js` の `DEFAULT_SETTINGS` が唯一の出所で、
起動のたびにそこから始まる。設定タブでの変更はその起動中（再読み込みするまで）だけ有効。
範囲外の入力は丸めて入力欄へ反映する。

端末に保存した古い値が新しい既定値を覆い隠さないため、運用方針を変えるときは
`js/constants.js` を書き換えて配布すれば全端末へ等しく効く（`sw.js` の `APP_VERSION` も
併せて改めること）。逆に、現地で変えた値を次回も使いたい場合は毎回設定し直す必要がある。

### 7-1. オフライン地図タイル

`data/tile_manifest.json` に記載されたタイルを Cache API へ一括取得する。

- 取得前に枚数と地図種別を確認する。進捗表示と中止が可能。
- 取得済み枚数・マニフェスト version・地図種別・取得日時を表示する（オフラインでも表示可）。
- 既にキャッシュ済みのタイルはスキップする。同時取得数は 4。
- Cache API が使えない環境では、その旨を表示してボタンを無効化する（起動は妨げない）。

### 7-2. アプリの更新

`sw.js` の `APP_VERSION` を版数として、「現行（動作中）」と「最新（サーバー）」を比較する。

- 版数の形式は `yyyy-mm-dd.n`（`yyyy-mm-dd` = 更新した日付、`n` = 同じ日付内の 1 から始まる連番。
  日付が変われば `n` は 1 に戻す）。例: `2026-07-30.1` → 同日中の再更新で `2026-07-30.2`。
- 設定タブを開くたびに確認し、新しい版があれば更新するか確認する。
- 表示中に新しい Service Worker が制御を握った場合も、再読み込みするか確認する。
- オフライン時は「最新バージョンを取得できませんでした」と表示する。

## 8. データ仕様

### 8-1. 保存される内容

保存は「調査日 → 地点 → 実データ」の 3 階層（4-6）。
実データは記録中に 5 エポックずつ**分割して**書かれ、読み出すときに結合される。

| 区分 | 内容 |
|---|---|
| 調査日 | 日付（`yyyy-mm-dd`）・ラベル・メモ・作成/更新日時 |
| 記録のメタ（地点） | 調査日・地点番号・**状態（下書き/確定）**・地点名・メモ・作成/終了日時・種別（記録/取込）・測定区間（4-9）・集計サマリ（中心・点数・DRMS・CEP50/95・停止理由・**収束判定の有無**・受信品質・生NMEA 行数・Android内蔵の DRMS と点数） |
| 記録の本体 | 調査日・地点番号 ＋ 集計値一式（実データは下記の分割ぶんを結合して取り出す） |
| 実データの分割 1 件 | 5 エポックぶんの生エポック群（＋生NMEA 行、＋並行取得した Android内蔵のサンプル群） |
| 生エポック 1 件 | UTC 時刻・受信時刻・緯度・経度・標高(MSL)・fix quality・測位モード・使用/視野内衛星数・PDOP/HDOP/VDOP・GST の緯度経度標準偏差・速度・進路・衛星リスト |
| 生NMEA 1 件 | 受信時刻 ＋ 受信した行そのもの |
| Android内蔵 1 件 | 測位確定時刻・受信時刻・緯度・経度・accuracy・楕円体高・速度・進路（衛星情報・DOP は取得できない） |
| 設定 | 7. の各設定値、タイルキャッシュの取得情報 |

生NMEA・Android内蔵のデータは、取得した記録にだけ付く。取得していない記録の形は従来どおり。

集計サマリの「収束判定の有無」（`autoStop`）は、停止サマリで「未収束」と「収束判定なし」を
書き分けるために保存する（4-3）。この項目を持たない旧データは「未収束」として扱う。

### 8-2. エクスポート形式

地点ごと:

| 形式 | 内容 | 用途 |
|---|---|---|
| CSV | 1 行 1 エポック（使用衛星の平均 C/N0 を含む）＋末尾に地点の識別と集計値のコメント行。BOM 付き UTF-8 | 表計算での分析 |
| GPX | 記録の中心を `wpt`、生エポック群を `trk` | 地図ソフト・GIS |
| NMEA | 受信した行そのもの（先頭に地点を示すコメント行） | RTKLIB など別ツールでの再解析 |
| JSON | メタ＋集計値＋生エポック（衛星リスト込み）＋生NMEA＋Android内蔵のサンプルと集計値。本アプリで取込可能 | バックアップ・端末間移動 |

調査日ごと（1 日ぶんをまとめて持ち出す）:

| 形式 | 内容 | 用途 |
|---|---|---|
| 対応表CSV | **1 行 1 地点**。先頭 2 列が調査日・地点番号。2 系統のばらつき（DRMS/CEP/標準偏差）、中心のズレ、DRMS 比、測定区間の対応（4-9）を横並びにする。列名は `gnss_*` / `dev_*` | 2 系統比較の入口 |
| バンドルJSON | その日の全地点を 1 ファイルに（各地点の生NMEA・生エポック・Android内蔵を含む） | 一括バックアップ・PC への持ち出し |

CSV と GPX は **GNSS受信機の行だけ**を出力する（Android内蔵はレートも点数も揃わず、
同じ表・同じ軌跡に混ぜると列や点の意味が壊れるため）。Android内蔵の比較値は
CSV 末尾のコメント行に `device_*` として付ける。2 系統を地点単位で並べて比べる場合は
対応表CSV を、生データが要る場合は JSON／バンドルJSON を使う。

## 10. 制約・既知の前提

- iPhone / iPad は Web Bluetooth 非対応のため利用できない。
- 記録は記録専用の端末で行う。データが 10 秒届かないと打ち切る（4-2）。
- 保存を押す前にアプリが終了した場合、直近の追記（5 秒ごと）以降のデータは失われる。
- ビープはブラウザの自動再生ポリシーにより、記録ボタンを押した時点で音を出す準備をする。
  端末が消音・音量 0 のときは鳴らない（振動は使わない）。
- 水平精度は GST が出力されない場合 HDOP × UERE の概算値であり、実測ばらつきではない。
- DRMS / CEP は「収集した点のばらつき」であり、真位置からの誤差（確度）ではない。
- Android内蔵GNSS の比較（4-8）には次の前提がある。
  - ブラウザからは生 NMEA・衛星情報・DOP を取得できないため、比較できるのは
    ばらつきの統計と中心のズレだけ。SkyPlot / SNR / DOP は GNSS受信機のみ。
  - 内蔵側は GNSS 単独ではなく WiFi / 基地局を融合した測位で、屋内や WiFi 密集地では
    「内蔵GNSS の実力」を測ったことにならない。
  - GNSS受信機と端末は物理的に離れた位置にあるため、中心のズレには設置位置の差が含まれる。
  - 静止中に OS が更新を間引くと内蔵側のばらつきが過小評価される（座標重複数で確認する）。
  - 時刻は端末時計（受信機は GPS 時刻）で、両者は厳密には一致しない。
- 保存データは端末内のみ。ブラウザのサイトデータを削除すると失われる（JSON 出力で退避する）。
