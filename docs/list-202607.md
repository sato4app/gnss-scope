# GNSS Scope 一覧タブ 機能まとめ（202607）

「一覧」タブでできることを1枚にまとめた解説。
仕様の正本は `funcspec-202607.md` 4-6・4-7・4-11・4-12、実装構成は `design-202607.md`、
操作手順は `usersGuide-202607.md` を参照。

実装は [../js/list-ui.js](../js/list-ui.js)（画面）、
[../js/package-io.js](../js/package-io.js)（出力ZIP の組み立てと取込）、
[../js/zip.js](../js/zip.js)（ZIP の読み書き）、
[../js/file-io.js](../js/file-io.js)（各ファイルの組み立て）に分かれている。

## 全体像

端末内（IndexedDB）に残っている測位データを **日ごと**に並べ、そこから持ち出して片付ける画面。
記録タブが「測る画面」、この画面が「持ち出して片付ける画面」。

```
調査日 2026-08-08（土）  20地点 ────────────── [📦 出力] [日ごと削除]
  ├ No.1 記録 2026-08-08-01 📷3     [読込][詳細][編集][出力][削除]
  ├ No.2 記録 2026-08-08-02 ⚠      [読込][詳細][編集][出力][削除]
  └ 下書き 14:12 停止               [保存][読込][削除]
```

| 関連モジュール | 役割 |
|---|---|
| [../js/list-ui.js](../js/list-ui.js) | 調査日ツリー・行の描画・各操作・容量警告 |
| [../js/package-io.js](../js/package-io.js) | 出力ZIP（manifest 組み立て・詰め込み・取込） |
| [../js/zip.js](../js/zip.js) | ZIP の書き出し／読み込み（CRC-32・deflate・store） |
| [../js/file-io.js](../js/file-io.js) | CSV / GPX / NMEA / JSON の組み立てと JSON 取込 |
| [../js/survey.js](../js/survey.js) | 調査日ごとのグループ化と集計 |
| [../js/view-utils.js](../js/view-utils.js) | 行に出すテキストの組み立て（純粋関数） |
| [../js/storage.js](../js/storage.js) | IndexedDB（読み出し・削除・書き出し記録） |

**一覧は `session` だけを読んで描く。** 実データ（チャンク）は結合しない。20地点×数日を
開くたびに結合していては待たされるため、行に出す値は保存時に `session.summary` へ入れてある。
実データを読むのは「読込」「出力」「詳細」を押したときだけ（詳細は集計値のみで足りる）。

## 1. 調査日の見出し

| 行 | 内容 |
|---|---|
| 見出し | 日付（曜日つき）・地点数・`下書き n件`・`書出済`・2系統が揃った地点数 |
| 1行目 | 測っていた時間帯・生NMEA を持つ地点数・合計エポック数 / 合計行数 |
| 2行目 | 平均DRMS（GNSS受信機 / Android内蔵）・写真枚数・データ量 |

集計は**確定済みの地点だけ**で数える（下書きが混ざると平均DRMSも両系統カウントも歪む）。
開いている調査日は操作後も開いたまま保つ。既定は**最新の調査日だけ**開く。

| ボタン | 内容 |
|---|---|
| 📦 出力 | その調査日を ZIP 1ファイルにまとめる（3.） |
| 日ごと削除 | 配下の地点と下書きをまとめて削除 |

出力すると見出しに `書出済` が付く。地点や写真が増えれば未書き出しへ戻る。

## 2. 地点の行

1行に詰め込まず、役割で3段に分ける。

```
No.2 [記録] 2026-08-08-02 📷3 ⚠
09:24:00–09:25:32（92秒）収束で自動停止  GNSS受信機 92点 DRMS 0.78m  Android内蔵 6点 DRMS 4.20m（ズレ 3.1m 北東）
(34.85361, 135.47202)  NMEA 92エポック / 1,104行  重なり 88秒（区間内 6/7点）  約 210 KB
```

| 段 | 内容 | 読み取れること |
|---|---|---|
| 1行目 | 地点番号・種別（記録／取込）・地点名・写真枚数・`⚠` | どの地点か |
| 2行目 | 測定区間・停止理由・2系統の点数と DRMS・中心のズレ | **測ったときのこと** |
| 3行目 | 中心座標・NMEA の量・区間の重なり・データ量 | **残っているもの** |

- **停止理由**を一覧に出すのは、未収束で打ち切った地点をその場で拾えるようにするため。
- **⚠（取りこぼしの警告）** は再測を検討する材料。次のいずれかで出す（内訳はツールチップ）。
  - 取得率が 90% 未満（1Hz なら秒数と点数はほぼ一致するはず）
  - 生NMEA の上限打ち切り／エポック欠落／BLE 欠落の推定／チェックサム NG
- **NMEA のエポック数はパース済み測位結果の点数と同じ値**（エポックを NMEA から組み立てているため）。
  生行を保存していない記録でもエポック数は出せるので、保存の有無は行数の側で示す
  （`NMEA 92エポック（生行は未保存）`）。
- **中心のズレ**は保存時に `summary` へ入れた値を使う。この項目を持たない古い記録では出ない。

| ボタン | 内容 |
|---|---|
| 読込 | 解析タブ・地図タブの対象にする（読込中の行は枠が青くなる） |
| 詳細 | 測位結果の全文（記録タブの停止直後と同じ並び）＋メモ |
| 編集 | 地点名・メモ・写真を後から直す |
| 出力 | その地点だけを ZIP 1ファイルに（構造は調査日ぶんと同じ） |
| 削除 | 確認のうえ削除（読込中なら読込データも解除） |

### 下書きの行

調査日の**先頭**に出る。`下書き` バッジと停止時刻を出し、操作は **保存 / 読込 / 削除** だけ
（出力は確定してから）。「保存」を押すとその行に地点名・メモの入力欄が開き、確定できる。
**アプリを再起動した後でも、ここから下書きを地点にできる。**
停止処理が走らないまま落ちた記録は `記録中に中断` と出る（集計値は読込・確定のときに作り直す）。
収集中の記録は `記録中` と出て操作できない。

## 3. 📦 出力（ZIP パッケージ）

1調査日（または1地点）を **ZIP 1ファイル**にまとめる。形式ごとのボタンは持たず、
**出力1つに集約**している（中身として全形式が入る）。

```
gnss-scope_2026-08-08.zip
├ manifest.json                     出力の索引
├ survey.json                       調査日メタ＋全地点のメタ・集計値（実データなし）
├ compare.csv                       対応表（1行1地点。2系統比較の入口）
└ points/p02_2026-08-08-02/
   ├ point.json                     地点まるごと（format 1。単体でも取込できる）
   ├ epochs.csv                     1行1エポック
   ├ device.csv                     1行1サンプル（Android内蔵）
   ├ track.gpx                      中心を wpt、生エポック群を trk
   ├ raw.nmea                       生NMEA（**完全無加工**）
   ├ raw_index.csv                  エポック ↔ raw.nmea の行番号
   └ photos/ph1.jpg …
```

### 生NMEA を無加工で置く

RTKLIB など別ツールへそのまま渡せることを優先し、`raw.nmea` には地点を示すコメント行も
入れない。そのぶん「どの地点のどのエポックのものか」は別に持つ必要があるので、
紐付けを **3重**にしてある。どれか1つが崩れても対応を辿れる。

1. **パス** — 同じ地点のファイルが同じディレクトリに同居する
2. **中身** — CSV は末尾コメント、JSON はフィールドに `survey_id` / `point_no` を持つ
   （`raw.nmea` だけは無加工なので持たない）
3. **manifest** — `points[]` が地点 → ディレクトリ・ファイル名・件数の対応表を持つ

### raw_index.csv（エポック ↔ 生行）

```
epoch_no,utc_time,recv_at_ms,recv_at_local,line_from,line_to,lines
0,,,,1,7,7
1,2026-08-08T00:24:31.000Z,1754612671412,2026-08-08 09:24:31,8,19,12
```

行番号は `raw.nmea` の1起点。エポックの `recvAt` は「そのエポックの最初のセンテンスを
受け取った時刻」なので、エポック k の行は `[recvAt_k, recvAt_{k+1})` に入る行として区切る。
**保存時にエポック境界そのものは持っていないため、これは受信時刻からの再構成（近似）**である。

- 先頭のエポックより前に届いた行は `epoch_no` 0（記録開始直後の途中から拾った塊）
- 最後のエポック以降の行は最後のエポックに含める（未確定の次エポックと区別できない）
- **行が0のエポックも1行として残す** — その区間の生行が落ちていた（BLE欠落・上限打ち切り）ことが分かる

### そのほか

- 写真を含めるかはチェックボックスで選ぶ（既定 ON）。1日ぶんは写真込みで 20〜25MB 程度。
- 圧縮は `CompressionStream('deflate-raw')`。非対応の環境では無圧縮（store）で詰める。
- 実データは**地点ごとに読んで詰め終わったら手放す**（20地点ぶんを一度にメモリへ並べない）。
- 出力中は進捗（`出力中… 3/20 地点`）を出し、二重に走らせない。
- 下書きは出力しない。地点1つだけの出力では `書出済` にしない（その日はまだ片付いていないため）。

## 4. 📂 読込（取込）

出力ZIP（format 3）・単体JSON（format 1）・バンドルJSON（format 2）を同じボタンで受ける
（拡張子で振り分ける）。

- 取込のたびに新しい id を採番するため、同じファイルを2回読んでも上書きにならない
  （元の id は `sourceId`、元の地点番号は `sourcePointNo` に保持）。
- 調査日は元データの日付をそのまま使い、地点番号だけ取込先で採り直す。
- 集計値が欠けている場合は生エポックから再計算する。
- ZIP からは**写真も復元**する。枚数・バイト数は取込先で数え直す
  （元データの枚数を持ち込むと、写真が無いのに `📷` が付いてしまう）。
- ZIP の生NMEA は無加工なので、**行ごとの受信時刻は `raw_index.csv` からエポック単位で復元**する
  （行そのものは元のまま。時刻だけが近似になる）。索引が無ければ時刻を持たない行として復元する。

## 5. 端末内のデータ量

記録データと写真は端末内に貯まり続けるため、量を自分で数えて警告する。

- 想定上限 100MB。**50MB を超えるとこのタブの先頭に警告を出し続ける**（記録は止めない）。
  警告を解決する手段（出力 → 削除）がこの画面にあるため、ここに出す。
- 合計と**未書き出しぶん**を併記する。どれを消してよいかがその場で分かるようにするため。
- 表示は書き込み時に数えた概算で、IndexedDB の実使用量とは一致しない
  （`navigator.storage.estimate` は地図タイルを含むため使わない）。

## 6. 注意点

- 一覧に出る値は保存時の `summary` 由来。**古い記録では新しい項目（中心のズレなど）が出ない。**
- 出力ZIP は端末内で組み立てる。外部送信は一切しない。
- ZIP の展開に `DecompressionStream` が要る（取込側）。書き出しは非対応環境でも無圧縮で通る。
