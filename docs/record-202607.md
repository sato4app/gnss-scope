# GNSS Scope 記録タブ 機能まとめ（202607）

「記録」タブでできることを、画面の流れに沿って1枚にまとめた解説。
仕様の正本は `funcspec-202607.md` 4章、判定式・算出式は `algospec-202607.md` 2〜3章、
操作手順は `usersGuide-202607.md` を参照。

実装は [../js/record-ui.js](../js/record-ui.js)（UI 配線）と
[../js/recorder.js](../js/recorder.js)（収集・集計ロジック）に分かれている。

## 全体像

**1回の記録 = 1地点**。静止点にとどまって連続エポックを収集し、測位のばらつきを集計する。

```
待機 ──[⏺記録]──> 収集中 ──[⏹停止/自動停止]──> 未保存 ──[💾保存]──> 保存済み（＝読込データ）
  ▲                                              │
  └──────────[記録（破棄を確認）]────────────────┘
```

| 関連モジュール | 役割 |
|---|---|
| [../js/record-ui.js](../js/record-ui.js) | ボタン配線・ライブ表示・記録一覧・Wake Lock |
| [../js/recorder.js](../js/recorder.js) | 収集・停止判定・保存（record / stop / save） |
| [../js/accuracy.js](../js/accuracy.js) | 集計（DRMS / CEP / 標準偏差）・収束判定・内蔵GNSS集計 |
| [../js/survey.js](../js/survey.js) | 調査日→地点のID体系・測定区間・グループ化 |
| [../js/file-io.js](../js/file-io.js) | CSV / GPX / NMEA / JSON の入出力 |
| [../js/charts.js](../js/charts.js) | 散布図の描画 |
| [../js/constants.js](../js/constants.js) | 記録パラメータの既定値（最低収集時間・上限時間・上限エポック数など） |

## 1. 現在の測位値（常時表示）

記録していない間も、次を毎エポック更新する。

| 項目 | 内容 |
|---|---|
| 緯度 / 経度 | 小数第7位まで |
| 標高(MSL) | GGA のジオイド補正後標高 |
| 推定水平精度 | GST があれば `±x.x m (GST)`、無ければ `±x.x m (HDOP×UERE)` |
| 衛星 使用/視野内 | GSA の使用衛星数 / GSV の視野内衛星数 |
| HDOP | 水平精度低下率 |

## 2. ⏺ 記録（開始）

- 有効な測位がない場合は開始せず警告する。未保存の記録があれば破棄の確認を行う。
- 開始時に **Wake Lock** を取得して画面を維持する（画面復帰時に自動で再取得）。
- 設定タブの値（上限時間・上限エポック数・自動停止・最低収集時間・端末内蔵GNSS 並行取得・
  生NMEA 保存）を引き継いで開始する。
- 蓄積対象は「緯度経度があり fix quality > 0」のエポックのみ。
- 画面OFF / バックグラウンドでは BLE が切れるため収集を一時停止する
  （`● REC` は表示のまま、点数が増えない状態になる）。

## 3. 収集中の表示

毎エポック更新される「収集状況」。

| 項目 | 内容 |
|---|---|
| 収集点数 / 経過時間 | 蓄積したエポック数と秒数 |
| DRMS(暫定) / CEP50(暫定) | その時点までのばらつき |
| 収束判定 | 下表のいずれか |
| 端末内蔵GNSS | 取得点数と平均 accuracy（未許可・非対応などの状態も表示） |
| 生NMEA | 蓄積行数（保存OFF なら `—（保存OFF）`） |

収束判定の表示:

| 表示 | 意味 |
|---|---|
| `—（自動停止OFF）` | 自動停止が無効 |
| `最低時間まで残り N 秒` | 最低収集時間に達していない |
| `待機中（品質不足）` | 品質ゲートを通るエポックが続いていない |
| `判定中（安定10秒待ち）` | 判定窓（10秒）を満たしていない |
| `安定 x.x m / DRMS±x.x m` | 直近10秒の中心移動量と DRMS 変動幅 |

あわせて**散布図**（中心からの東西×南北オフセット）をライブ描画する。

## 4. ⏹ 停止 と集計

### 停止理由

| 停止理由 | 条件 |
|---|---|
| 手動停止 | 停止ボタン押下 |
| 自動停止: 収束（中心・DRMS横ばい） | 自動停止ON かつ最低収集時間経過後、中心移動 ≤0.3 m・DRMS 変動 ≤0.3 m（または DRMS の5%）が10秒継続 |
| 自動停止: 上限時間到達（未収束） | 経過時間 ≥ 上限時間（0 = 無効） |
| 自動停止: 上限エポック到達 | 収集点数 ≥ 上限エポック数（0 = 無効） |

収束判定には品質ゲート（3D fix・HDOP ≤ 3・使用衛星 5個以上）があり、
外れたエポックが出ると「安定して10秒」の連続カウントをやり直す。

### 集計値

停止時に次を算出する（[../js/accuracy.js](../js/accuracy.js) の `computeStaticStats`）。

- 中心（平均緯度経度）・中央値
- 東西 / 南北の標準偏差 [m]
- DRMS・2DRMS
- CEP50・CEP95（中心からの半径誤差の経験的パーセンタイル）
- 標高の平均・標準偏差
- 収集エポック数・fix 種別の内訳
- 平均 PDOP / HDOP / VDOP・平均衛星数・使用衛星の平均 C/N0
- 中心からのオフセット（散布図用）
- **その測定区間の受信品質**（CS NG・未対応文・破棄文字・エポック欠落・GSV部分欠落・
  BLE欠落推定・Pico 統計の差分）

この時点では**まだ保存されない**（未保存の記録）。

## 5. 💾 保存

地点名・メモを入力して IndexedDB へ保存する。

- 保存時に**調査日**（`yyyy-mm-dd`。端末のローカル日付）と**地点番号**（その日の連番）を
  自動採番する。地点名の既定値は `yyyy-mm-dd-01` 形式。メモは任意。
- 地点番号は**欠番を再利用しない**（同じ調査日の最大値＋1）。一度出した対応表と番号がずれないため。
- 1地点の NMEA と端末内蔵GNSS は**同じレコード**に入るため、地点の対応が構造上ずれない。
- 保存後はそのまま「読込データ」になり、解析タブ・地図タブの対象になる。

## 6. 端末内蔵GNSS の並行取得（比較）

設定「記録中に端末内蔵GNSSも取得して比較する」（既定 ON）。
記録中だけスマートフォン自身の測位も並行収集し、**同じ時刻・同じ場所**で MAX-M10S と比較する。

| 項目 | 仕様 |
|---|---|
| 取得区間 | 記録中（record 〜 stop）のみ。常時取得はしない |
| 取得手段 | ブラウザの Geolocation API（`watchPosition`、高精度モード） |
| 収集内容 | 時刻・緯度・経度・accuracy（68%円半径）・楕円体高・速度・進路 |
| 一時停止 | 画面OFF / バックグラウンドでは M10S 側と同じく停止 |
| 集計 | M10S と同じ定義（DRMS / CEP50 / CEP95 / 標準偏差）＋ 平均 accuracy・座標重複数・M10S 中心からのズレ（距離と16方位） |

注意点として結果テキストに常に併記されるもの:

- **座標重複**: 静止中は OS が測位更新を間引き、直前と同一の座標を返し続けることがある。
  ばらつきを過小評価する（内蔵の方が優秀に見える）ため重複点数を必ず示し、
  全体の30%以上なら注意文を添える。
- 内蔵側は GNSS 単独ではなく WiFi / 基地局を融合した測位（Fused Location）である。

衛星リスト・DOP・fix 種別・生NMEA はブラウザから取得手段がないため、
比較は「ばらつきの統計」同士に留め、エポック単位の1対1比較は行わない。

## 7. 生NMEA の保存

設定「生NMEA行もそのまま保存する」（既定 ON）。
受信した NMEA 行を、パースを通す前に**そのまま**記録へ残す（RTKLIB など別ツールでの再解析用）。

- チェックサム NG 行・`$PPICO` も「受信したそのまま」として含める。
- 容量の目安: 1地点（30〜180秒）あたり 40〜250 KB、20地点/日で 3〜5 MB 程度。
- 上限 20000 行を超えたぶんは保存せず、超過した行数を記録に残して途中までであることを示す。
- 地点ごとに `.nmea` テキストとして書き出せる。

## 8. 測定区間の対応検証

停止時に2系統それぞれの測定区間と重なりを記録に残す（[../js/survey.js](../js/survey.js) の `buildWindow`）。

| 項目 | 意味 |
|---|---|
| NMEA の区間 | エポックが取れていた時刻範囲と点数 |
| Android の区間 | 測位が取れていた時刻範囲と点数 |
| 重なり | 重なった秒数と、各区間に占める割合 |
| 記録区間内の点数 | Android のサンプルのうち record〜stop の間に受信した点数 |
| 端末時計 − GPS時刻 | 2系統を同じ時間軸へ並べ直すときの補正量 |
| Android の測位の古さ | 受信時刻 − OS が測位を確定した時刻 |

M10S の時刻は GPS 時刻、Android の時刻は OS が測位を確定した時刻で**別の時計**である
（`maximumAge` を 0 にしても数秒前に確定した測位が返ることがある）。
区間の突き合わせは両者に共通する「アプリが受信した時刻」で行い、上記2項目でズレを示す。

「記録区間内の点数」を割合と別に持つのは、静止中に OS が更新を間引いて Android が
1〜数点しか返さない場合、割合だけでは対応を判断できないため。

## 9. 記録一覧（調査日 → 地点のツリー）

1日に何十地点もまわる前提の2階層表示。調査日ごとの折りたたみで表示する。

### 調査日の見出し

日付・地点数・2系統が揃った地点数（両系統 / NMEAのみ / Androidのみ）・平均DRMS（NMEA と Android）。

### 調査日の操作

| ボタン | 内容 |
|---|---|
| 📊 対応表CSV | 1行1地点で NMEA と Android を並べた比較表（2系統比較の入口） |
| 📦 バンドルJSON | その日の全地点を1ファイルに（生NMEA・生エポック・Android 測位すべて込み） |
| 日ごと削除 | 配下の地点をまとめて削除 |

### 地点の行

地点番号・種別（記録／取込）・地点名・日時・点数・DRMS（内蔵DRMS）・中心座標に加え、
2系統の対応（NMEA の点数 / 生NMEA 行数 / Android の点数 / 記録区間内の点数）。

### 地点の操作

**読込** / **CSV** / **GPX** / **NMEA** / **JSON** / **削除**（削除は確認あり）。
NMEA は生NMEA が保存されている地点でのみ押せる。

読込中の記録は強調表示する。読込中の記録を削除した場合は読込データを解除する。
調査日が空になったら、その調査日自体も片付ける。

## 10. 📂 JSON取込

本アプリが出力した JSON を読み込み、この端末の一覧に追加する。
単体（1地点）と調査日バンドル（その日の全地点）のどちらも同じボタンで読める。

- 検証: `session` / `point` / `point.samples`（1件以上）の存在。
  不足時はどの地点が不正かを添えてエラー表示する。
- 取込のたびに新しい id を採番するため、同じファイルを2回読んでも上書きにならない
  （元の id は `sourceId`、元の地点番号は `sourcePointNo` に保持）。
- 調査日は元データの日付をそのまま使い、地点番号だけ取込先で採り直す。
- 集計値が欠けている場合は生エポックから再計算する。

## 11. エクスポート形式まとめ

| 形式 | 単位 | 内容 | 主な用途 |
|---|---|---|---|
| CSV | 地点 | 全エポック（17列）＋ 地点情報・集計値・内蔵GNSS比較をコメント行に | Excel（BOM付き UTF-8） |
| GPX | 地点 | 中心を `wpt`、生エポック群を `trk` | 地図ソフト・GIS |
| NMEA | 地点 | 受信した生行そのまま | RTKLIB 等での再解析 |
| JSON | 地点 | セッション＋地点を丸ごと（読み戻し可、format 1） | バックアップ・端末間移動 |
| 対応表CSV | 調査日 | 1行1地点、NMEA と Android を並べた比較表 | 2系統の比較分析 |
| バンドルJSON | 調査日 | その日の全地点（format 2） | 一括持ち出し |

いずれもローカル処理で、**外部送信は一切行わない**。

## 12. 注意点

- **記録は画面表示中のみ有効**。画面OFF / バックグラウンドでは BLE が切断され、
  収集が一時停止する（`● REC` は表示のまま点数が増えない）。
- 停止しても保存はされない。保存するまでは「未保存の記録」であり、
  新しい記録を始めると破棄される（確認ダイアログあり）。
- 保存先は端末内の IndexedDB のみ。端末を移す場合は JSON でエクスポート／取込する。
