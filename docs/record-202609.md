# GNSS Scope 記録タブ 機能まとめ（202609）

「記録」タブでできることを、画面の流れに沿って1枚にまとめた解説。
仕様の正本は `funcspec-202609.md` 4章、判定式・算出式は `algospec-202609.md` 2〜3章
（散布図の表示半径は 6章）、操作手順は `usersGuide-202609.md` を参照。

実装は [../js/record-ui.js](../js/record-ui.js)（収集フローの UI 配線）と
[../js/recorder.js](../js/recorder.js)（収集・集計ロジック）に分かれている。
保存した記録の一覧・出力は「一覧」タブ（[../js/list-ui.js](../js/list-ui.js)。`list-202609.md`）。

## 全体像

**1回の記録 = 1地点**。静止点にとどまって連続エポックを収集し、測位のばらつきを集計する。

```
待機 ──[⏺記録]──> 収集中 ──[⏹停止/自動停止]──> 下書き ──[💾保存]──> 地点（＝読込データ）
                     │                          │
                5秒ごとに追記                [🗑破棄]──> 削除
```

**記録中も 5 秒ごとに保存される。** 保存を押す前にアプリが終了しても、直前までは
「下書き」として残り、一覧から確定できる。「下書き」は停止しただけでまだ地点になっていない
記録で、地点番号を持たず、調査日の集計にも出力の対象にもならない。

### 2 系統の呼び方

受信機は入れ替える可能性があるため、画面と出力に機種名は出さない。
**GNSS受信機**（BLE で生 NMEA を送ってくる機器）と **Android内蔵**（端末自身の測位）の
2 語だけを使う。実体は [../js/constants.js](../js/constants.js) の `SERIES` が唯一の出所。
「NMEA」はデータ形式の名前であって系統名ではない（「生NMEA」等はそのまま使う）。

## 1. 現在の測位値（折りたたみ）

記録していない間も、次を毎エポック更新する。**記録中は自動で畳んで**進捗バーと散布図に
画面を譲り、停止すると開く。

| 項目 | 内容 |
|---|---|
| 緯度 / 経度 | 小数第7位まで |
| 標高(MSL) | GGA のジオイド補正後標高 |
| 推定水平精度 | GST があれば `±x.x m (GST)`、無ければ `±x.x m (HDOP×UERE)` |
| 衛星 使用/視野内 | GSA の使用衛星数 / GSV の視野内衛星数 |
| HDOP | 水平精度低下率 |

## 2. ⏺ 記録（開始）

- 有効な測位がない場合は開始せず警告する。
- **下書きを作ってから収集を始める。** 作れなければ記録しない（残せない記録は始めない）。
  下書きは残るので、記録開始時に前の記録の破棄を迫ることはしない。
- 開始時に **Wake Lock** を取得して画面を維持する（画面復帰時に自動で再取得）。
- ブラウザの自動再生ポリシーのため、**このボタンの押下でビープ音の準備をする**
  （停止時に初めて用意しても鳴らないため）。
- 設定タブの値（上限時間・上限エポック数・自動停止・最低収集時間・Android内蔵の並行取得・
  生NMEA 保存）を引き継いで開始する。
- 蓄積対象は「緯度経度があり fix quality > 0」のエポックのみ。
- 散布図と測位結果は、**最初の記録を始めるまで表示しない**（空の正方形で画面を埋めない）。
- **最後のエポックから 10 秒が過ぎたら記録を打ち切る（データ途絶）。**
  画面OFF・他アプリへの切替・BLE 切断・受信機の電池切れ・fix 喪失を一様に拾う。
  データが届かないまま続けると、穴の空いた区間が 1 地点として残るため。
  復帰後は続きではなく**別の地点として測り直す**。
- 記録には**記録専用の端末**を使う。地図や写真は別のスマートフォンで見る。
- 収集中は **5 エポック（≒5 秒）ごとに実データを下書きへ追記する。**
  書き込みに失敗したら記録タブに赤字で出し、次の追記で再試行する
  （収集済みは捨てない）。連続 3 回失敗したら打ち切る。

## 3. 収集中の表示

**同じ値を 2 か所に出さない。** 置き場所は 1 か所ずつに決めている。

| 内容 | 置き場所 |
|---|---|
| 点数・実測秒数・DRMS（2 系統とも） | 散布図の下の凡例 |
| 経過時間・収束の進み具合 | 進捗バー |
| 停止した理由 | 測位結果の見出し |
| それ以外の明細 | 測位結果を開いた中 |

### 進捗バー

| バー | 内容 |
|---|---|
| 主バー「経過」 | 経過 / 上限時間。最低収集時間の位置にマーカー。上限時間 0（無制限）なら経過秒のみ |
| 副バー「最低時間」 | 最低収集時間までの残り |
| 副バー「安定待ち」 | 品質の良いエポックが連続で溜まった秒数 / 10秒。品質不良でリセットされると 0 に戻り、色を変えて戻ったことを示す |
| 副バー「判定中」 | 10秒の窓が揃った後。中心移動・DRMS幅の「実測値 / 許容値」をゲージで出し、許容内なら緑 |

窓が揃っても中心が動いていれば停止しないため、「安定待ち」と「判定中」を分ける
（バーが満タンのまま止まらない状態を説明できるようにするため）。
自動停止 OFF なら副バーは出さない。バーの脇に品質ゲート条件
（使用/視野内衛星数・HDOP・測位モード）を出し、止まらない理由の手掛かりにする。

### 散布図と凡例

```
● GNSS受信機   45秒間 132点  DRMS 1.24m
◎ Android内蔵  45秒間  14点  DRMS 4.81m
```

- 記号は**色だけでなく形でも**区別する（塗り ● / 中抜き ◎）。直射日光下や
  色覚特性では色が頼れないため。散布図の点の描き分けも同じ。
- 点数だけを並べると「内蔵は点が少ない＝劣る」と読めてしまう。受信機が 1Hz なのに対し
  内蔵は OS が更新を間引くだけなので、**実測の秒数を併記**する。
- Android内蔵が 1 点も取れていないときは状態を出す（`— 取得OFF` / `— 未許可` /
  `— 測位できません` / `— この端末/ブラウザは非対応`）。
- 表示範囲の外に出た点は縁に▲でクランプし、凡例の下に系統別の件数を出す。

## 4. ⏹ 停止 と集計

### 停止理由と知らせ方

| 停止理由 | 条件 | ビープ音 | 測位結果の見出し |
|---|---|---|---|
| 収束 | 自動停止ON かつ最低収集時間経過後、中心移動 ≤0.3 m・DRMS 変動 ≤0.3 m（または DRMS の5%）が10秒継続 | 短く2回（2400Hz） | `収束で自動停止（45秒/45点）` |
| 上限時間到達 | 経過時間 ≥ 上限時間（0 = 無効） | 長く1回（900Hz） | `上限時間で停止（未収束: 180秒/180点）` |
| 上限エポック到達 | 収集点数 ≥ 上限エポック数（0 = 無効） | 長く1回（900Hz） | `上限エポックで停止（未収束: 150秒/300点）` |
| 手動停止 | 停止ボタン押下 | 鳴らさない | `手動停止（未収束: 20秒/20点）` |
| データ途絶 | 最後のエポックから 10 秒 | 長く1回（900Hz） | `データ途絶で停止（未収束: 45秒/40点）` |
| 保存失敗 | 記録中の追記が連続 3 回失敗 | 長く1回（900Hz） | `保存失敗で停止（未収束: 60秒/58点）` |

- 手動停止で鳴らさないのは、操作した本人が停止を分かっているため。
  データ途絶・保存失敗は本人が分かっていないので鳴らす（受信が切れたと気付けるほうが有用）。
- 音のパターンで「良い結果で終わった」と「未収束のまま打ち切った」を区別できるので、
  画面を見ずに移動してよいか測り直すかを判断できる。
- 自動停止 OFF のときは「未収束」ではなく `収束判定なし: ` と書く（判定していないため）。
- 有効なエポックが 1 点も無い場合は `測位データなしで停止（30秒/0点）`。
- 秒数と点数を併記するのは、1Hz なら本来一致する 2 つがずれていれば取りこぼし
  （BLE 欠落・中断）があったと分かるため。
- ビープは設定「自動停止をビープ音で知らせる」（既定 ON）で切れる。消音・音量0では鳴らない。

収束判定には品質ゲート（3D fix・HDOP ≤ 3・使用衛星 5個以上）があり、
外れたエポックが出ると「安定して10秒」の連続カウントをやり直す。

### 測位結果（折りたたみ）

見出しには**停止条件だけ**を出し、明細は開いたときだけ見せる（現地で見るのは
散布図と凡例で足りるため）。開閉状態は保持する（一度開けば次の記録でも開いたまま）。
明細は「集計値 → 2系統の比較 → 測定区間」の順。

### 集計値

停止時に次を算出する（[../js/accuracy.js](../js/accuracy.js) の `computeStaticStats`）。

- 中心（平均緯度経度）・中央値
- 東西 / 南北の標準偏差 [m]
- DRMS・2DRMS
- CEP50・CEP95（中心からの半径誤差の経験的パーセンタイル）
- 標高の平均・標準偏差
- 収集エポック数・fix 種別の内訳
- 平均 PDOP / HDOP / VDOP・平均衛星数・使用衛星の平均 C/N0
- 中心からのオフセット（散布図用）
- **その測定区間の受信品質**（CS NG・未対応文・破棄文字・エポック欠落・GSV部分欠落・
  BLE欠落推定・Pico 統計の差分）

この時点で実データと集計値は**下書きへ書き終わっている**。ただし**まだ地点ではない**。

停止後の扱い:

- 有効エポックが 0 点なら、下書きごと削除する（復元しても使えないため）。
- **経過 30 秒以上で有効エポックが 10 点未満**なら、破棄するかを確認する。
  1Hz なら 30 秒で 30 点が期待値で、10 点未満は取りこぼしが大きい。集計は 1 点でも
  計算できてしまうため、そのまま地点にすると DRMS がほぼ 0 という偽の「良い値」が残る。
  確認は結果を描画した後に出す（下書きは書けているので、答えないまま放置しても失われない）。

## 5. 💾 保存（確定）と 🗑 破棄

地点名・メモを入力して下書きを**確定**する。**このとき初めて地点になる。**

- 確定時に**地点番号**（その日の連番）を採番する。地点名の既定値は `yyyy-mm-dd-01` 形式。
  メモは任意。**調査日**（`yyyy-mm-dd`。端末のローカル日付）は記録開始の時点で決まっている。
- **地点番号は確定済みの記録だけを見て採る。** 下書きは番号を消費しないので、
  測り直した失敗記録を捨てても番号が飛ばない。
- 地点番号は**欠番を再利用しない**（同じ調査日の最大値＋1）。一度出した対応表と番号がずれないため。
- 確定は集計値と地点名の更新だけで、実データには触らない（既に書けているため）。
- 1地点の GNSS受信機と Android内蔵のデータは**同じレコード**に入るため、地点の対応が構造上ずれない。
- 確定後はそのまま「読込データ」になり、解析タブ・地図タブの対象になる。
- **🗑 破棄**を押すと、確認のうえ下書きと実データをまとめて削除する。

### 地点の写真

保存フォームの **📷 写真を追加** から、現地の写真を地点に付けられる（既定 5 枚まで）。

- 撮った写真は**取り込む時点で縮小**して保存する。後から縮められないため、大きいまま貯めない。
- 縮小後の長辺は設定タブで **1280 / 640 / 320 px** から選ぶ（既定 1280）。
  1枚あたりの目安は 200KB / 60KB / 20KB 程度。
- 上限枚数も設定タブで変えられる。0 枚にすると写真機能を出さない。
- **写真を付けられるのは確定（`💾 保存`）の前だけ。** 後から足す画面は持たない。
- 写真は端末内にのみ保存され、外部へ送信しない。出力ZIP には同梱できる（既定 ON）。

## 6. Android内蔵GNSS の並行取得（比較）

設定「記録中に Android内蔵GNSS も取得して比較する」（既定 ON）。
記録中だけスマートフォン自身の測位も並行収集し、**同じ時刻・同じ場所**で GNSS受信機と比較する。

| 項目 | 仕様 |
|---|---|
| 取得区間 | 記録中（record 〜 stop）のみ。常時取得はしない |
| 取得手段 | ブラウザの Geolocation API（`watchPosition`、高精度モード） |
| 収集内容 | 時刻・緯度・経度・accuracy（68%円半径）・楕円体高・速度・進路 |
| 打ち切り | 記録が停止すれば内蔵側の収集も止まる（一時停止という状態は持たない） |
| 集計 | GNSS受信機と同じ定義（DRMS / CEP50 / CEP95 / 標準偏差）＋ 平均 accuracy・座標重複数・受信機の中心からのズレ（距離と16方位） |

注意点として結果テキストに常に併記されるもの:

- **座標重複**: 静止中は OS が測位更新を間引き、直前と同一の座標を返し続けることがある。
  ばらつきを過小評価する（内蔵の方が優秀に見える）ため重複点数を必ず示し、
  全体の30%以上なら注意文を添える。
- 内蔵側は GNSS 単独ではなく WiFi / 基地局を融合した測位（Fused Location）である。

衛星リスト・DOP・fix 種別・生NMEA はブラウザから取得手段がないため、
比較は「ばらつきの統計」同士に留め、エポック単位の1対1比較は行わない。

## 7. 生NMEA の保存

設定「生NMEA行もそのまま保存する」（既定 ON）。
受信した NMEA 行を、パースを通す前に**そのまま**記録へ残す（RTKLIB など別ツールでの再解析用）。

- チェックサム NG 行・`$PPICO` も「受信したそのまま」として含める。
- 容量の目安: 1地点（30〜180秒）あたり 40〜250 KB、20地点/日で 3〜5 MB 程度。
- 上限 20000 行を超えたぶんは保存せず、超過した行数を記録に残して途中までであることを示す。
- 地点ごとに `.nmea` テキストとして書き出せる。

## 8. 測定区間の対応検証

停止時に2系統それぞれの測定区間と重なりを記録に残す（[../js/survey.js](../js/survey.js) の `buildWindow`）。

| 項目 | 意味 |
|---|---|
| GNSS受信機 の区間 | エポックが取れていた時刻範囲と点数 |
| Android内蔵 の区間 | 測位が取れていた時刻範囲と点数 |
| 重なり | 重なった秒数と、各区間に占める割合 |
| 記録区間内の点数 | Android内蔵のサンプルのうち record〜stop の間に受信した点数 |
| 端末時計 − GPS時刻 | 2系統を同じ時間軸へ並べ直すときの補正量 |
| Android内蔵 の測位の古さ | 受信時刻 − OS が測位を確定した時刻 |

受信機の時刻は GPS 時刻、内蔵の時刻は OS が測位を確定した時刻で**別の時計**である
（`maximumAge` を 0 にしても数秒前に確定した測位が返ることがある）。
区間の突き合わせは両者に共通する「アプリが受信した時刻」で行い、上記2項目でズレを示す。

「記録区間内の点数」を割合と別に持つのは、静止中に OS が更新を間引いて内蔵が
1〜数点しか返さない場合、割合だけでは対応を判断できないため。

## 9. 保存した後（一覧タブ）

保存して地点になった記録の一覧・読込・出力・削除・取込は「**一覧**」タブが持つ。
記録タブは「測る画面」に絞ってある。一覧に並ぶのは**調査日**までで、1地点ずつ見るときは
その日を読み込み、解析タブ・地図タブの地点セレクタで切り替える。詳しくは `list-202609.md` を参照。

## 10. 注意点

- **記録は記録専用の端末で行う**。データが 10 秒届かないと打ち切る。
  復帰後は続きではなく別の地点として測り直す。
- 停止しただけでは地点にならない。保存するまでは「下書き」で、地点番号も持たない。
  ただし**下書きは消えない**ので、後から一覧タブで確定できる。
  中身のある下書きを自動で消すことはない（起動時に片付けるのは、実データを 1 件も
  持たない下書きだけ）。
- 保存先は端末内の IndexedDB のみ。端末を移す場合は一覧タブの **📦 出力**（ZIP）で書き出して取り込む。
- **端末内のデータ量は自分で数えて警告する。** 想定上限 100MB、50MB を超えると一覧タブに
  警告が出る（記録は止めない）。合計と「未書き出しぶん」を併記するので、
  WiFi のある場所で調査日ごとに出力し、不要な調査日を削除して減らす。
  表示は書き込み時に数えた概算で、IndexedDB の実使用量とは一致しない。
